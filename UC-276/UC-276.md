# DESCRIPTION

## 1. Objetivo

UC-276 implementa un **sistema avanzado de solicitud recursiva (recursive prompting)** para flujos de trabajo basados en agentes. La solicitud recursiva es una técnica en la que el agente **reutiliza su propia salida como entrada para refinarla** iterativamente. En lugar de producir una respuesta única y seguir adelante, crea un bucle: **generar → evaluar → refinar → aceptar/repetir**.

El sistema integra dos patrones complementarios:
1. **Recursive Prompting**: refinamiento iterativo de outputs (generate → critique → refine → commit).
2. **RSI (Recursive Self-Improvement)**: auto-mejora profunda estilo Gödel Agent (propose → verify → apply → benchmark → evaluate → learn).

```
┌─────────────────────────────────────────────────────────────────┐
│     DOS CARAS DE LA AUTO-MEJORA EN AGENTES                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  AUTORREFLEXION (UC-275)                                         │
│     Foco: PARAMETROS INTERNOS del agente                         │
│     Ciclo: actuar -> medir -> ajustar parametros                 │
│                                                                  │
│  RECURSIVE PROMPTING (UC-276)                                    │
│     Foco: OUTPUT generado por el agente                          │
│     Ciclo: generar -> revisar -> mejorar output                  │
│                                                                  │
│  SINERGIA                                                        │
│     Recursive Prompting mejora el OUTPUT                         │
│     Autorreflexion ajusta los PARAMETROS que producen ese output │
│     Juntos = auto-mejora completa                                │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### El Ciclo Recursivo Fundamental

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│    ┌──────────┐                                              │
│    │ GENERATE │<------------------------------┐              │
│    └────┬─────┘                               │              │
│         v                                     │              │
│    ┌──────────┐                               │              │
│    │ EVALUATE │ <- QualityCriteria            │              │
│    └────┬─────┘                               │              │
│         v                                     │              │
│    Cumple estandar?                           │              │
│      /        \                               │              │
│    SI          NO                             │              │
│     v           v                             │              │
│  ┌────────┐  ┌───────────┐                    │              │
│  │ COMMIT │  │ REFINE    │--------------------┘              │
│  │(final) │  │(feedback) │                                   │
│  └────────┘  └───────────┘                                   │
│                                                              │
│  PROPIEDAD CLAVE: cada version es INPUT de la siguiente      │
│  La salida V_n se convierte en entrada de V_{n+1}            │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 2. Arquitectura del Sistema

| 3. Estancamiento | `stagnation.py` | StagnationDetector: plateau, oscilacion, degradacion |
| 4. Orquestacion | `recursive_prompter.py` | RecursivePrompter (7 fases) + RSILoop (Godel Agent) |

## 3. Criterios de Calidad

El QualityEvaluator evalua outputs contra 5 criterios ponderados:

| Criterio | Peso | Umbral Min | Target | Heuristica |
|---|---|---|---|---|
| `clarity` | 0.25 | 0.50 | 0.85 | Longitud promedio de oraciones (optimo ~60 chars) |
| `conciseness` | 0.20 | 0.40 | 0.80 | Ratio output/input (ideal 0.3-0.7) |
| `completeness` | 0.25 | 0.50 | 0.85 | Cobertura de palabras clave del input |
| `accuracy` | 0.20 | 0.60 | 0.90 | Mejora progresiva con iteraciones |
| `coherence` | 0.10 | 0.50 | 0.80 | Presencia de conectores logicos |

---

## 4. Las 8 Estrategias de Refinamiento

| Estrategia | Descripcion | Cuando se usa |
|---|---|---|
| `clarify` | Oraciones cortas, vocabulario simple | clarity < target |
| `concise` | Eliminar redundancias, reducir 30% | conciseness < target |
| `expand` | Agregar detalles y contexto | completeness < target |
| `correct` | Corregir errores identificados | issues detectados |
| `restructure` | Reorganizar con secciones y flujo | coherence < target |
| `validate` | Verificar precision de afirmaciones | accuracy < target |
| `optimize` | Optimizar para objetivo especifico | relevance < target |
| `adapt_audience` | Adaptar tono y nivel para audiencia | audiencia especifica |

La seleccion es automatica: ataca el criterio mas debil primero.

---

## 5. Deteccion de Estancamiento

El StagnationDetector previene iteraciones inutiles con 3 detectores:

| Patron | Condicion | Accion |
|---|---|---|
| **Plateau** | N iteraciones con mejora < 0.02 | Detiene ciclo |
| **Oscilacion** | Scores fluctuando sin progreso neto | Detiene ciclo |
| **Degradacion** | Score baja > 0.05 respecto a anterior | Rollback |

---

## 6. RSI Loop (Recursive Self-Improvement)

Implementa el patron Godel Agent de auto-mejora profunda:

1. **PROPOSE** — el agente propone una modificacion.
2. **VERIFY** — verifica que no rompe especificaciones.
3. **APPLY & TEST** — aplica en sandbox, ejecuta pruebas.
4. **BENCHMARK** — ejecuta tareas de referencia.
5. **EVALUATE** — compara con resultados previos; si mejora, conserva; si no, revierte.
6. **LEARN** — registra resultado y actualiza conocimiento.

Solo sobreviven las mejoras que funcionan. `logic_version` se incrementa con cada mejora aceptada.

# API

## Card Views — Entrada

### `POST /api/v1/agent/create`
Crea un agente de recursive prompting con ID unico.
```json
{"agent_id": "research_agent"}
```

### `POST /api/v1/recursive/run`
Ejecuta ciclo recursivo completo: GENERATE->EVALUATE->REFINE->COMMIT. El agente reutiliza su propia salida como entrada para refinarla iterativamente.
```json
{
  "agent_id": "research_agent",
  "input_data": "El machine learning es un subcampo de la inteligencia artificial que permite a los sistemas aprender de datos...",
  "task_description": "Genera un resumen ejecutivo claro y conciso",
  "context": {"audience": "ejecutivos", "objective": "decision de inversion"},
  "initial_version": null
}
```

### `POST /api/v1/recursive/refine`
Aplica una sola iteracion de refinamiento a un texto con estrategia especifica.
```json
{
  "content": "El texto a refinar...",
  "strategy": "clarify",
  "task_description": "Improve clarity",
  "context": {"objective": "claridad", "audience": "tecnicos"}
}
```

### `POST /api/v1/recursive/evaluate`
Evalua calidad de un texto contra criterios multi-dimension (clarity, conciseness, completeness, accuracy, coherence).
```json
{
  "content": "El texto a evaluar...",
  "original_input": "El input original para comparar cobertura",
  "task_description": "Summarize"
}
```

### `POST /api/v1/recursive/rsi`
Ejecuta ciclo RSI (Recursive Self-Improvement) estilo Godel Agent: Propose->Verify->Apply->Benchmark->Evaluate->Learn.
```json
{
  "agent_id": "rsi_default",
  "task": "Optimiza este algoritmo de sorting",
  "current_output": "La implementacion actual del algoritmo...",
  "max_cycles": 5
}
```

### `POST /api/v1/recursive/stagnation/check`
Verifica si una trayectoria de scores esta estancada (plateau, oscilacion, degradacion).
```json
{"trajectory": [0.5, 0.55, 0.56, 0.56, 0.55]}
```

## 10. Diferencia con UC-275 (Autorreflexion)

| Aspecto | UC-275 (Autorreflexion) | UC-276 (Recursive Prompting) |
|---|---|---|
| **Foco** | Parametros internos del agente | Output generado |
| **Ciclo** | ACT -> OBSERVE -> EVALUATE -> REFLECT -> REFINE | GENERATE -> EVALUATE -> REFINE -> COMMIT |
| **Mejora** | Ajusta configuracion (risk, weights) | Refina el texto/contenido producido |
| **Memoria** | Episodica (lecciones aprendidas) | Historial de versiones (trajectory) |
| **Estancamiento** | N/A (max iterations) | Plateau + Oscilacion + Degradacion + Rollback |
| **Estrategias** | Por causa raiz (6 categorias) | Por criterio debil (8 estrategias) |
| **RSI** | No | Si (Godel Agent pattern) |
| **Sinergia** | UC-275 ajusta COMO produce | UC-276 mejora QUE produce |
