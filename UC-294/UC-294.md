# UC-294 — Situational Awareness Middleware (SAM): AGI funcional para trading de ticks

## Resumen

UC-294 extiende UC-293 añadiendo una **capa de conciencia situacional funcional** inspirada en la **Global Workspace Theory (GWT)** y en modelos de metacognición computacional. El objetivo es que el agente no solo prediga ticks y filtre planes con Juice, sino que **conozca su propio estado**, la calidad del entorno y la coherencia interna antes de actuar.

SAM actúa como una "corteza prefrontal" software que:

- Centraliza la percepción del entorno (`EnvironmentState`).
- Mantiene un **Self-Model** con confianza, carga cognitiva y perfil de competencias.
- Registra una **memoria episódica de trabajo** de capacidad limitada.
- Ejecuta **broadcast del workspace global** a todos los módulos.
- Aplica un **monitor metacognitivo** que decide `PROCEED`, `REVIEW` o `ABORT`.
- Conserva el **Safety Supervisor** como última barrera física antes de ejecutar.

Todo el intercambio entre módulos sigue un **contrato JSON estricto** (`Envelope`) trazable y auditable.

## Componentes SAM

### 1. MemoryEpisode (Memoria Episódica)

Unidad de memoria de trabajo de corto plazo con:

- `event_type`: PERCEPTION, ACTION, OBSERVATION, METACOGNITION, REFLECTION.
- `content`: descripción textual.
- `timestamp` y `metadata`.

Capacidad limitada (`max_memory_items`, por defecto 7), siguiendo el principio de memoria de trabajo restringida.

### 2. EnvironmentState (Aquí y Ahora)

Hechos situacionales del entorno digital:

- `system_clock`: timestamp actual.
- `api_health`: HEALTHY / DEGRADED.
- `market_volatility`: NORMAL / ELEVATED / HIGH.
- `active_alerts`: alertas externas.
- `data_quality`: proporción de ticks recibidos vs. esperados.
- `latency_ms`.

### 3. Self-Model (Modelo del Agente)

Representación estructurada del agente:

- `agent_identity`, `current_goal`.
- `competence_profile`: puntuaciones por tarea (análisis técnico, sentimiento, riesgo, predicción de ticks).
- `confidence_level`: confianza calibrada con base en errores recientes.
- `cognitive_load`: LOW / MEDIUM / HIGH.
- `recent_errors`: contador de fallos en memoria.

La calibración de confianza aplica reglas operativas:

- ≥2 errores recientes: confianza –0.30, carga HIGH.
- 1 error: confianza –0.10, carga MEDIUM.
- 0 errores: recuperación gradual.

### 4. WorkspaceContent (Global Workspace)

Espacio global de capacidad limitada que contiene:

- `perception`: snapshots y señales.
- `environment`: estado situacional.
- `self_model`: estado interno.
- `memory`: episodios recientes.
- `hypotheses`: hipótesis candidatas.
- `selected_hypothesis`: hipótesis más saliente.
- `broadcast`: flags para todos los módulos (`context_alert`, `low_self_confidence`, `high_volatility`).

### 5. MetacognitionModule

Evalúa, en tiempo de ejecución, si el agente debe actuar:

| Condición | Acción |
|---|---|
| `confidence_level < 0.5` | `ask_human_help` |
| `api_health != HEALTHY` | `reflect` |
| `market_volatility == HIGH` | `reduce_exposure` |
| `data_quality < 0.5` | `ask_human_help` |
| Señales BUY y SELL fuertes al mismo tiempo | `reflect` |
| Capacidad menor a 0.6 para la acción propuesta | `delegate` |

Resultado: `recommendation` ∈ {`PROCEED`, `REVIEW`, `ABORT`}.

### 6. SafetySupervisor

Última barrera antes de ejecutar:

- Verifica `stop_loss`.
- Verifica `confidence >= min_signal_confidence`.
- Verifica exposición total vs. `max_position_pct`.
- Si falla, devuelve `rollback` con `REVERT_TO_HOLD`.

### 7. Envelope (Contrato JSON)

Sobre estándar para mensajes entre módulos:

```json
{
  "envelope_version": "1.0",
  "source": "global_workspace",
  "destination": "risk_module",
  "message_type": "broadcast",
  "timestamp": "2026-09-02T...",
  "payload": {...},
  "metadata": {...}
}
```

## Pipeline de ejecución

```text
1. Ingesta de ticks/noticias
2. CentralBrain.observe() → snapshots + beliefs
3. SAM.build_workspace() → EnvironmentState + Self-Model + Memory + Hypotheses
4. SAM.broadcast_to_modules() → todos los módulos reciben el workspace
5. MetacognitionModule.evaluate() → PROCEED / REVIEW / ABORT
6. Si ABORT → respuesta `aborted_by_sam`
7. Si PROCEED/REVIEW → BDI.build_beliefs/desires/intention
8. ConfrontationalJuice.confront() → approved / distilled / rejected
9. SafetySupervisor.check() → rollback si es necesario
10. Risk gate + ejecución
11. Registrar episodios en memoria
12. Episodios SAM + observaciones de ejecución → WorldModelObservation → reentrenamiento del cerebro
```

## Cómo SAM alimenta el World Model y realiza aprendizaje

El middleware situacional no solo decide si actuar: **genera experiencias de entrenamiento** para el cerebro probabilístico. Esto se hace en `agent_core.py` mediante un único objeto `CentralBrain` compartido entre SAM y el grafo LangGraph:

1. **Cerebro compartido**: `run_sam_aware_pipeline()` crea una única instancia de `CentralBrain`. Ese mismo objeto se pasa a `run_agent(..., central_brain=brain)`, por lo que `perceive`, `simulate`, `execute` y `learn` leen y escriben en el mismo `world_model`.

2. **Hipótesis iniciales**: SAM consulta `brain.predict_next_price(symbol)` para cada ticker y construye hipótesis con `confidence = 1 - uncertainty`. Así el workspace global contiene una predicción del cerebro antes de que BDI/Juice la examine.

3. **Episodios como observaciones**: después de la ejecución del grafo, cada episodio de memoria SAM (`PERCEPTION`, `ACTION`, `OBSERVATION`, `METACOGNITION`) se convierte en una `WorldModelObservation`:
   - `actual_success = False` si el contenido contiene `ERROR`, `FALLO` o `REJECTED`.
   - `reward = +1.0 / -1.0` según éxito/fracaso.
   - `action_type` = tipo de evento, `symbol` desde metadatos.

   La función `_feed_sam_memory_to_world_model()` realiza esta conversión y llama a `brain.world_model.update_from_observation(...)`.

4. **Observaciones del grafo**: las observaciones generadas en el nodo `execute` (éxito/fallo de órdenes, PnL) también se registran como episodios SAM y se alimentan al cerebro.

5. **Reentrenamiento online**: si tras alimentar todas las observaciones se cumple `observations_since_train >= retrain_after`, se ejecuta `brain.world_model.retrain()`, actualizando los tres MLPs (`model_success`, `model_reward`, `model_next_return`) con las nuevas experiencias.

6. **Persistencia**: el cerebro entrenado puede guardarse con `ModelPersistence` (`joblib` + `model_metadata.json`) y recargarse en siguientes ejecuciones, por lo que el Self-Model de SAM hereda un cerebro cada vez más calibrado.

En resumen, SAM funciona como una **corteza prefrontal que también supervisa el aprendizaje del neocórtex (world model)**: no solo decide si actuar, sino que etiqueta las consecuencias de cada decisión y las devuelve al cerebro para mejorar predicciones futuras.

## API REST — Card view de entrada

### `POST /api/v1/sam/workspace`

```json
{
  "symbols": ["AAPL"],
  "ticks": [...],
  "news": [],
  "portfolio": {"cash": 100000, "positions": {}},
  "snapshots": {...},
  "signals": [{"side": "BUY", "confidence": 0.8, "agent": "technical"}],
  "hypotheses": [{"name": "buy_dip", "confidence": 0.8, "risk_score": 0.2}],
  "alerts": ["API degradada"],
  "agent_identity": "UC294.Alpha"
}
```

| Campo | Tipo | Requerido | Descripción |
|---|---|---|---|
| `symbols` | list[string] | Sí | Activos |
| `ticks` | list[object] | Sí | Ticks de mercado |
| `portfolio` | object | No | Cash y posiciones |
| `snapshots` | object | No | Snapshots pre-calculados |
| `signals` | list[object] | No | Señales de analistas |
| `hypotheses` | list[object] | No | Estrategias candidatas |
| `alerts` | list[string] | No | Alertas externas |
| `agent_identity` | string | No | Identidad del agente |

### `POST /api/v1/trading/plan_with_sam`

Igual que `plan_with_bdi`, pero ejecuta el pipeline completo SAM → BDI → Juice → World Model → Ejecución.

## Seguridad, trazabilidad y MLOps

1. **Contrato JSON estricto** (`Envelope`): todo mensaje entre módulos es versionado, con source/destination y payload serializable.
2. **Memoria episódica limitada**: evita parálisis por análisis y emula atención humana.
3. **Self-model calibrable**: la confianza se ajusta con errores observados; puede reemplazarse por un modelo RL sin tocar el resto.
4. **Metacognición operativa**: no afirma conciencia subjetiva; es un monitor de control ejecutivo con políticas explícitas.
5. **Doble barrera de seguridad**: metacognición + Juice + SafetySupervisor.
6. **Listo para microservicios**: cada módulo puede desplegarse como sidecar/FastAPI/gRPC; `Envelope` es el contrato Protobuf natural.
7. **Trazabilidad completa**: de la señal bruta al workspace, a la decisión metacognitiva, al veredicto Juice y a la ejecución, todo queda registrado en `working_memory` y `reflections`.
