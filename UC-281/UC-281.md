# Tomo III — UC-281

## Sincronización multi-framework para TrackPrice.ai

UC-281 implementa un plano de control común para coordinar **LangGraph, CrewAI, Microsoft Agent Framework/AutoGen, Google ADK y AWS Strands Agents**. Cada framework conserva su especialidad, pero se comunica mediante contratos normalizados, una barrera de sincronización, consenso ponderado, guardrails e idempotencia.

La implementación funciona sin claves en modo determinista. En modo `auto`, usa SDK nativo únicamente cuando está instalado; cada respuesta informa `native: true/false`. Nunca crea, sustituye ni registra claves API.

## Responsabilidades por framework

| Framework | Rol en TrackPrice | Estado en este entorno |
|---|---|---|
| LangGraph | Grafo de estado, herramientas y validación | SDK nativo ejecutado |
| CrewAI | Analista cuantitativo + estratega de pricing | Adapter con fallback determinista |
| MAF/AutoGen | Debate de noticias y sentimiento | Adapter con fallback determinista |
| Google ADK | Sesión, inventario y herramientas | Adapter con fallback determinista |
| AWS Strands | Política tool-first de margen/competencia | Adapter con fallback determinista |

Al instalar un SDK opcional, el adapter lo detecta. Un adapter solo puede marcar `native=true` cuando realmente ejecuta una integración nativa; el fallback queda identificado con `warnings: ["deterministic_fallback"]`.

## Contrato común

### AgentRequest

- `run_id`: ejecución global.
- `correlation_id`: correlación entre frameworks.
- `framework`: destino.
- `task`: instrucción normalizada.
- `state`: snapshot inmutable del mercado.
- `context`: resultados previos/contexto.
- `idempotency_key`: evita duplicados.
- `deadline`: límite absoluto.

### AgentResponse

- Framework y nombre del adapter.
- Indicador `native`.
- Confianza normalizada 0–1.
- Precio propuesto.
- Sentimiento -1–1.
- Rationale, métricas, warnings y latencia.

## Sincronización extrema

1. El Core captura un único snapshot versionado.
2. Publica `run.started`.
3. Los cinco adapters se ejecutan en paralelo.
4. Cada adapter recibe el mismo estado, correlation ID y deadline.
5. La barrera espera quorum mínimo de tres respuestas.
6. Las respuestas se normalizan y ordenan de forma estable.
7. Se calcula consenso ponderado por confianza.
8. La dispersión reduce la confianza global.
9. Los guardrails deciden `recommend`, `review` o `execute`.
10. El closed loop asimila solo una fracción del cambio.
11. Estado, eventos y hash se persisten para auditoría.

## Consenso y guardrails

```text
recommended_price = sum(price_i * confidence_i) / sum(confidence_i)
dispersion_rate   = population_std(prices) / median(prices)
consensus_conf    = avg(confidence) * (1 - min(1, dispersion * 3))
applied_price     = current + assimilation_rate * (safe_price - current)
```

Guardrails:

- Quorum mínimo: 3 frameworks.
- Desacuerdo alto: dispersión superior a 8%.
- Confianza mínima: 60%.
- Piso: costo + 10%.
- Techo: precio competidor + 20%.
- Variación máxima: 10% por ciclo.
- Fallo parcial explícito.
- Dry-run por defecto.
