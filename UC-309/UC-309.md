# UC-309 — Capa Transversal y Externa de Observabilidad Agentic

## 1. Propósito

UC-309 responde la pregunta: **¿qué ocurrió dentro de una ejecución concreta del agente y por qué terminó así?**

- **UC-308** detecta degradación histórica comparando evaluaciones contra baselines.
- **UC-309** captura el ciclo estructurado `thought-summary → action → observation` de cada ejecución.
- **UC-325** evalúa internamente la calidad del razonamiento.
- **UC-290** construye el expediente de decisiones de riesgo.
- **UC-300** autoriza cada llamada a herramienta.
- **UC-324** contiene, bloquea o revierte acciones.

UC-309 es la **fuente canónica** de eventos; adaptadores de LangSmith, LangFuse y LangGraph solo mapean formatos externos al modelo propio. No se almacena razonamiento privado (chain-of-thought literal), ni secretos, ni credenciales en bruto.

## 2. Arquitectura

```
Agentes / UCs
    │
    ▼
Adapters (LangSmith / LangFuse / LangGraph)
    │
    ▼
Canonical Events  (models_309.py)
    │
    ├── Privacy Guard  → redact, pseudonymize, allowlist, sampling
    │
    ▼
Trace Store  → hash-chain audit, TTL, RBAC
    │
    ├── Trace Correlator  → reconstruct & validate
    ├── Metrics Aggregator → Prometheus text
    ├── Anomaly Detector  → immediate alerts
    ├── Alert Manager     → in-memory ack
    └── Exporters         → Loki JSONL, Tempo/OTLP spans, Prometheus text
    │
    ▼
Flask API  / UC-308 feed
    │
    ▼
Grafana Stack  (Prometheus + Loki + Tempo + Grafana)
```

### 2.1 Fronteras y control

- **UC-309 no es autoridad de autorización**: delega el contenido de UC-300, UC-290 y UC-324 en sub-eventos canónicos.
- **Sin credenciales ni SDKs de terceros**: los adaptadores mapean payloads, nunca ejecutan llamadas de red.
- **API in-memory**: exportaciones son locales/simuladas; no hay conectividad real a Prometheus/Loki/Tempo/Grafana.
- **Separación de preocupaciones**: el agente envuelto por `agent_observer.py` no conoce la infraestructura de observabilidad.

## 3. Modelo canónico

El evento canónico (`models_309.py`) no almacena:

- Prompts completos del modelo.
- Chain-of-thought privada.
- Secretos, tokens, claves ni credenciales.

Sí almacena:

| Campo | Descripción |
|-------|-------------|
| `trace_id`, `span_id`, `parent_span_id` | Identificación de traza y spans |
| `execution_id`, `session_id`, `agent_id`, `agent_version` | Contexto de ejecución |
| `step`, `event_type` | Paso y tipo de evento |
| `model_request_meta` | Modelo, `max_tokens`, `temperature`, `tools_declared` (sin prompt) |
| `model_completion_meta` | Modelo, `finish_reason`, `tool_calls_proposed` (sin texto completo) |
| `structured_reasoning_summary` | Resumen estructurado, no pensamiento crudo |
| `action_proposed`, `action_proposed_hash` | Acción propuesta y su hash |
| `uc300` | `tool_name`, `policy_verdict`, `authorized`, `toctou_check`, `approved_action_hash` |
| `uc290` | `decision_id`, `risk_score`, `override`, `escalation` |
| `uc324` | `containment_type`, `contained_action` |
| `tool_name`, `tool_call_id`, `tool_result_status`, `observation_summary`, `observed_action_hash` | Resultado de la herramienta |
| `error`, `final_outcome` | Error y resultado final |
| `evidence_refs`, `dossier_refs` | Referencias al expediente y evidencia |
| `latency_ms`, `input_tokens`, `output_tokens`, `estimated_cost_usd` | Costes y rendimiento |
| `retries`, `steps`, `loop_count` | Reintentos, pasos y bucles |
| `labels` | Labels de cardinalidad controlada |
| `redaction_findings`, `pii_pseudonyms`, `allowlist_violations` | Hallazgos de privacidad y auditoría |
| `previous_event_hash`, `event_hash` | Cadena inmutable de hashes |

## 4. Privacidad y seguridad

`privacy_guard.py` aplica:

1. **Redacción recursiva** de secretos/credenciales/tokens (claves y valores).
2. **Pseudonimización HMAC** de PII (correos, teléfonos, patrones similares a SSN).
3. **Allowlist estricta** de campos; campos extra son eliminados y reportados.
4. **Límite de tamaño** de payload/evento/traza.
5. **TTL y límite de registros** en `trace_store.py`.
6. **Control de acceso RBAC** para recuperación de trazas.
7. **Muestreo** de trazas normales y captura forzada de errores, riesgo y anomalías.
8. **Cardinalidad controlada** de labels: nunca se usa `trace_id`, `span_id`, `session_id` o `execution_id` como label.
9. **Cadena inmutable de hashes** con `previous_event_hash` / `event_hash`.
10. **Rechazo/transformation de chain-of-thought privada**; se convierte en `structured_reasoning_summary` o `[SUMMARY_ONLY]`.

## 5. Macroproceso y subprocesos

1. **Emisión** (`agent_observer.py` / API) genera evento bruto.
2. **Sanitización** (`privacy_guard.py`) redacta, pseudonimiza y valida allowlist.
3. **Almacenamiento** (`trace_store.py`) mantiene el hash-chain, TTL y RBAC.
4. **Correlación** (`trace_correlator.py`) reconstruye la traza y detecta:
   - `missing_trace_start` / `missing_trace_end`
   - `broken_parent_span`
   - `action_without_observation`
   - `approved_vs_observed_action_divergence`
   - `loop_repeated_tools` / `loop_repeated_reasoning`
   - `hash_chain_broken`
5. **Agregación** (`metrics_aggregator.py`) genera métricas Prometheus sin labels de alta cardinalidad.
6. **Detección** (`anomaly_detector.py`) emite alertas in-memory con recomendaciones.
7. **Exportación** (`exporters_309.py`) genera JSON lines para Loki y spans OTLP-like para Tempo.
8. **Consumo** (`monitoring_generator_309.py`) produce feed para UC-308 de análisis longitudinal.

## 6. Integraciones

- **LangSmith / LangFuse / LangGraph**: `adapters_309.py` traduce payloads a eventos canónicos. No se usan SDKs ni se realizan llamadas de red.
- **Prometheus**: `/metrics` expone métricas en formato text exposition.
- **Loki**: `/logs` devuelve JSON lines con trace_id en la línea, no como label.
- **Tempo / OTLP**: `/spans` devuelve spans OTLP-like en JSON.
- **UC-308**: `monitoring_generator_309.py` genera un feed longitudinal serializable.

## 7. API (Flask)

Definiciones en `INPUT_CARDS` y `OUTPUT_CARDS` (`api_309.py`).

| Método | Ruta | Rol mínimo | Descripción |
|--------|------|-----------|-------------|
| GET | `/health` | — | Estado |
| GET | `/schema` | — | INPUT/OUTPUT cards |
| POST | `/events` | analyst | Ingesta un evento |
| POST | `/batch` | analyst | Ingesta un lote |
| GET | `/traces` | viewer | Listar trazas |
| GET | `/traces/<id>` | viewer | Ver traza (con redacción según rol) |
| GET/POST | `/traces/<id>/validate` | analyst | Validar traza |
| GET | `/metrics` | — | Métricas Prometheus |
| GET | `/logs` | analyst | Loki JSON lines |
| GET | `/spans` | analyst | Spans OTLP-like |
| GET | `/alerts` | auditor | Listar alertas |
| POST | `/alerts/<id>/ack` | analyst | Reconocer alerta |
| GET | `/status` | — | Resumen |
| POST | `/retention` | admin | Configurar retención |
| POST | `/reset` | admin | Limpiar store |

Roles: `viewer`, `analyst`, `auditor`, `admin`. Se aceptan por header `X-UC309-Role` o campo `role` en JSON. Para trazas sensibles se aplican redacciones según rol.

```promql
/
sum(rate(uc309_tool_calls_total[5m])) by (tool_name)
```

**Loki — filtrar un trace sin usar trace_id como label:**
```logql
{agent_id="uc315"} |= "trace-xxx"
```

**Tempo — buscar por `traceId` en la UI de Grafana TraceQL:**
```traceql
{ traceId = "trace-xxx" }
```

## 9. Control, contingencia y trazabilidad

- **Hash-chain**: cada evento referencia `previous_event_hash` del evento anterior de la traza.
- **RBAC**: trazas y alertas protegidas por rol.
- **Alertas in-memory**: no acciones automáticas; UC-308 consume métricas para decisiones históricas.
- **Divergencia aprobada-vs-observada**: detección de TOCTOU / manipulación.
- **Límite de tamaño y TTL**: control de retención y memoria.
- **Pérdida de telemetría**: métrica `uc309_telemetry_incomplete_total` y alerta correspondiente.

### Endurecimiento de privacidad y acceso

- La clave HMAC configurada en cada instancia de `PrivacyGuard` determina realmente los pseudónimos; dos tenants con claves diferentes no producen el mismo identificador para la misma PII.
- La recuperación de trazas y spans exige rol `viewer` o superior.
- La lectura de logs exige rol `analyst` o superior.
- La lectura y reconocimiento de alertas exige rol `auditor` o `admin`.
- Las métricas Prometheus no usan `trace_id`, `span_id`, `session_id` ni `execution_id` como labels.
