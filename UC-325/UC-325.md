# UC-325 — Motor de Bucles de Razonamiento Autorreflexivos (RLE)

## 1. Propósito y Alcance

Los bucles de razonamiento permiten a los agentes evaluar iterativamente la idoneidad de su recuperación inicial, analizar y refinar las consultas, e integrar nueva información antes de llegar a conclusiones. Cada bucle actúa como un control de calidad, ayudando a eliminar alucinaciones o contexto irrelevante y permitiendo que el agente converja en respuestas más precisas y multifacéticas.

UC-325 es una **capa independiente** que se inserta entre MP-04 (ReAct+ToT) y MP-05 (Decisión BDI) del cerebro AGI UC-315. **No modifica UC-315**: lo envuelve, consume sus salidas de razonamiento/retrieval, las evalúa, refina, y retorna una señal mejorada.

### Problema que resuelve

El cerebro AGI UC-315 presenta seis limitaciones arquitectónicas:

| # | Limitación | Módulo afectado |
|---|-----------|----------------|
| 1 | Nadie verifica si las memorias recuperadas son relevantes | `brain_memory_pipeline.py` |
| 2 | Queries de retrieval fijas, nunca se modifican | `_retrieve_relevant_memories()` |
| 3 | MetacognitiveMonitor diagnostica DESPUÉS, no DURANTE | `metacognitive_monitor.py` |
| 4 | No hay loop razone→evalúe→refine→razone dentro del mismo request | `self_awareness_loop.py` |
| 5 | `_synthesize()` en ToT es un solo paso ponderado | `react_tot.py` |
| 6 | Veredictos de calidad se guardan para el futuro, no modifican razonamiento actual | `continuous_self_eval.py` |

### Principios

- **UC-315 decide, UC-322 resuelve, UC-324 contiene, UC-317 ejecuta, UC-325 verifica.**
- **Un modelo genera evidencia. La evidencia no es una orden.**
- UC-325 verifica que el razonamiento sea correcto ANTES de decidir.

## 3. Fases del Bucle de Razonamiento

### 3.1 DISCOVER (Descubrimiento)

Recuperación inicial con expansión semántica de queries.

**Entradas:** Query del usuario, dominio.
**Salidas:** Chunks recuperados, hipótesis preliminares.

Actividades:
1. Expandir query original en variantes semánticas.
2. Recuperar chunks con cada variante.
3. Deduplicar chunks (por fingerprint SHA-256 y Jaccard).
4. Filtrar por relevancia mínima.
5. Generar hipótesis preliminares basadas en chunks.

### 3.2 REFINE (Refinamiento)

Evaluación de retrieval + detección de alucinaciones + re-recuperación.

**Entradas:** Estado con chunks e hipótesis.
**Salidas:** Chunks adicionales, hipótesis refinadas, gaps identificados.

Actividades:
1. Evaluar calidad colectiva del retrieval (relevancia, cobertura, redundancia).
2. Identificar hipótesis débiles (confianza 0.3-0.7).
3. Generar queries de verificación para hipótesis débiles.
4. Re-recuperar evidencia confirmatoria y contradictoria.
5. Identificar gaps de conocimiento.
6. Penalizar hipótesis sin soporte.

### 3.3 SYNTHESIZE (Síntesis)

Integración de hipótesis y resolución de conflictos.

**Entradas:** Hipótesis evaluadas, evidencia acumulada.
**Salidas:** Respuesta integrada, citations.

Actividades:
1. Detectar contradicciones entre chunks.
2. Resolver conflictos entre hipótesis (merge, refute).
3. Ordenar hipótesis por confianza.
4. Construir respuesta integrada con top-3 hipótesis.
5. Generar citations con chunk_id, source, score.

### 3.4 CONVERGE (Convergencia)

Evaluación final y decisión de continuar o parar.

**Entradas:** Estado completo post-síntesis.
**Salidas:** Veredicto (converged/max_rounds/stalled/etc.).

Actividades:
1. Evaluar 5 dimensiones de calidad (quality gates).
2. Detectar alucinaciones y aplicar correcciones.
3. Calcular confianza actual y trayectoria.
4. Verificar convergencia (delta < threshold).
5. Detectar estancamiento.
6. Decidir: parar o iterar.

## 4. Dimensiones de Calidad

| Dimensión | Descripción | Umbral | Peso |
|-----------|-------------|--------|------|
| **Relevance** | Pertinencia de chunks al query | 0.70 | 0.25 |
| **Coverage** | Completitud (aspectos cubiertos / requeridos) | 0.60 | 0.20 |
| **Consistency** | Coherencia entre hipótesis y evidencia | 0.80 | 0.25 |
| **Confidence** | Confianza proporcional a la evidencia | 0.75 | 0.20 |
| **Novelty** | Información nueva por iteración | 0.30 | 0.10 |

Quality gate: **todas** las dimensiones deben superar su umbral para pasar.

---

## 5. Detección de Alucinaciones

Seis tipos detectados durante el razonamiento (no después):

| Tipo | Descripción | Acción |
|------|-------------|--------|
| `claim_without_evidence` | Afirmación sin chunks de soporte | Buscar evidencia o reducir confianza |
| `fabricated_source` | Referencia a chunk inexistente | Eliminar referencia, reducir confianza |
| `confidence_inflation` | Confianza >> evidencia disponible | Ajustar confianza a nivel de evidencia |
| `contradiction_with_evidence` | Hipótesis contradice chunks | Refutar hipótesis |
| `extrapolation_beyond_data` | Certeza absoluta sin evidencia fuerte | Requerir evidencia adicional |
| `temporal_inconsistency` | Datos temporalmente inconsistentes | Marcar para revisión |

## 6. Refinamiento de Queries

Reemplaza las queries estáticas de `brain_memory_pipeline._retrieve_relevant_memories()`.

| Estrategia | Cuándo | Ejemplo |
|-----------|--------|---------|
| **expand** | Query inicial | "ejemplos concretos de X", "causas y consecuencias de X" |
| **specialize** | Alta redundancia | "X en el contexto de trading" |
| **verify** | Hipótesis débiles | "evidencia que soporte: Y", "argumentos en contra de: Y" |
| **generalize** | Baja relevancia | Eliminar calificadores, solo keywords |
| **gap-targeting** | Gaps identificados | Queries específicos por gap |

---

## 7. Convergencia

El bucle se detiene cuando se cumple **cualquiera** de:

| Criterio | Descripción |
|----------|-------------|
| **Converged** | Todas las quality gates pasan Y confianza >= 0.6 |
| **Confidence converged** | Delta entre rondas < 0.02 Y confianza >= 0.6 |
| **Max rounds** | Se alcanzó el límite de iteraciones (default: 5) |
| **Stalled** | Sin progreso por N rondas consecutivas |
| **Insufficient data** | Sin chunks después de >= 2 rondas |
| **Hallucination detected** | Severidad >= 0.8 |

## 8. Modelos de Datos

### ReasoningConfig

```python
ReasoningConfig(
    max_rounds=5,
    min_convergence_delta=0.02,
    stall_threshold=2,
    max_chunks_per_round=10,
    max_hypotheses=20,
    chunk_dedup_threshold=0.85,
    min_chunk_score=0.3,
    hallucination_threshold=0.5,
    quality_thresholds={
        "relevance": 0.70, "coverage": 0.60,
        "consistency": 0.80, "confidence": 0.75, "novelty": 0.30,
    },
)
```

### ReasoningState

Estado persistente a través del bucle:
- `query`, `domain`, `trace_id`
- `all_chunks`: Dict[str, RetrievedChunk]
- `hypotheses`: Dict[str, Hypothesis]
- `gaps`: Dict[str, KnowledgeGap]
- `iterations`: List[LoopIteration]
- `confidence_trajectory`: List[float]
- `final_answer`, `final_confidence`, `verdict`, `citations`

### ReasoningResult

Resultado final:
- `query`, `domain`, `trace_id`
- `answer`, `confidence`, `verdict`, `success`
- `rounds_executed`, `total_chunks_retrieved`, `duration_ms`
- `citations`, `quality_scores`, `hypotheses`
- `gaps_remaining`, `hallucination_reports`, `convergence_trajectory`

## 14. Modos de Fallo y Fallback

| Fallo | Comportamiento |
|-------|---------------|
| Sin retriever | Usa `StubRetriever` con knowledge base de ejemplo |
| Sin LLM | Usa `StubHypothesisGenerator` determinista |
| Chunks vacíos | Veredicto `INSUFFICIENT_DATA` después de 2 rondas |
| Alucinaciones severas (>= 0.8) | Veredicto `HALLUCINATION_DETECTED`, abort |
| Estancamiento | Veredicto `STALLED` después de N rondas sin progreso |
| Excepción | Capturada, log ERROR, veredicto `INSUFFICIENT_DATA` |
| Max rounds | Veredicto `MAX_ROUNDS`, retorna mejor hipótesis disponible |

## 15. Seguridad y Límites

- No modifica UC-315 canónico.
- No expone secrets ni API keys.
- Queries limitados por `max_expansions` (default 5).

- Detección de prompt injection delegada a la capa de contención UC-324.
