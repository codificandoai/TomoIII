# UC-293 — LLM Juice: Filtro Adversarial BDI + ReAct + CoT para Trading de Tick de Acciones

## Resumen

UC-293 eleva el agente de trading de UC-292 de "reactivo" a **cognitivo y autocrítico**. El modelo propone planes de trading, pero antes de comprometerse con una orden pasa por un **filtro adversarial** (`ConfrontationalJuice`) que confronta el plan contra las **Creencias** estrictas del sistema (precios, indicadores, sentimiento, incertidumbre del world model) y los **Deseos** (restricciones de riesgo y rentabilidad). Si el plan no sobrevive, se descarta o se destila a una acción segura (`HOLD` / `ESCALATE_HUMAN`).

El filtro puede evaluar tanto la **acción final** como toda la **cadena de razonamiento ReAct + CoT**, detectando saltos lógicos entre observaciones y conclusiones.

## Modelo BDI

### Beliefs (Creencias)

Hechos derivados del mercado y del portafolio. No son opiniones del LLM:

- `current_price`: último precio observado.
- `latest_features`: RSI, MACD, ATR, Bollinger, OBV, volatilidad, tendencia.
- `regime`: régimen de mercado (trending_bullish, ranging, etc.).
- `news_sentiment`, `news_credibility`: sentimiento agregado y credibilidad de fuentes.
- `world_model_uncertainty`: incertidumbre del predictor de ticks.
- `predicted_next_price`: siguiente precio estimado por el cerebro.
- `portfolio_cash`, `portfolio_position`, `cost_basis`: estado real del portafolio.

### Desires (Deseos)

Objetivos y restricciones duras que nunca pueden violarse:

- Maximizar retorno ajustado por riesgo.
- Nunca operar sin señal con confianza mínima.
- Nunca exceder `max_position_pct` ni `max_drawdown_pct`.
- Nunca ignorar una tendencia técnica contradictoria.

### Intention (Intención)

Plan candidato con traza ReAct/CoT. Permanece como `draft` hasta que el Juice emite un `survival_score >= 80` y se fija `is_committed = True`.

## Filtro Confrontacional Juice

El motor `ConfrontationalJuice.confront(beliefs, desires, intention)` aplica una batería de chequeos con puntuación inicial 100:

| Chequeo | Penalización | ¿Qué detecta? |
|---|---|---|
| Confianza de señal baja | -25 | Operar sin señal sólida |
| Sin stop-loss | -15 | Riesgo ilimitado |
| Sin take-profit | -10 | Sin objetivo definido |
| Incertidumbre del world model alta | -20 | Predicción poco confiable |
| Volatilidad extrema | -20 | Mercado inestable |
| Acción contra la tendencia | -15 | Comprar en tendencia bajista, etc. |
| RSI extremo | -10 | Sobrecompra/sobreventa |
| Sentimiento contradictorio | -10 | Comprar con noticias muy negativas |
| Tamaño de posición excesivo | -20 | Exposición por encima del límite |
| Precio predicho desfavorable | -10 | Modelo predice pérdida para el lado propuesto |
| Salto lógico en CoT | -10 | Observaciones ignoradas en la conclusión |

Resultado:

- `score >= 80`: **approved**, se fija compromiso.
- `50 <= score < 80`: **distilled**, se reduce tamaño pero no se aprueba directamente.
- `score < 50`: **rejected**, fallback a `HOLD` o `ESCALATE_HUMAN`.

## Integración con el grafo LangGraph

El grafo de UC-292 se extiende con un nodo intermedio:

```text
START → perceive → analyze → validate → plan → simulate → evaluate
                                              ↓
                                    adversarial_confrontation
                                              ↓
                                     risk_gate → confirm_or_execute
```

- `evaluate` selecciona la mejor estrategia.
- `adversarial_confrontation` convierte la estrategia en BDI y la confronta con Juice.
- Si el veredicto es rechazo drástico, la ejecución se detiene.
- Si es destilado, se corrige la estrategia (por ejemplo, reduciendo tamaño).

## API REST — Card view de entrada

### `POST /api/v1/bdi/state`

```json
{
  "symbols": ["AAPL"],
  "ticks": [...],
  "news": [...],
  "portfolio": {"cash": 100000, "positions": {}},
  "constraints": {"max_position_pct": 0.2, "max_drawdown_pct": 0.05},
  "risk_tolerance": "moderate",
  "selected_strategy": null,
  "signals": [],
  "evaluations": []
}
```

| Campo | Tipo | Requerido | Descripción |
|---|---|---|---|
| `symbols` | list[string] | Sí | Activos |
| `ticks` | list[object] | Sí | Serie de ticks |
| `news` | list[object] | No | Noticias |
| `portfolio` | object | No | Efectivo y posiciones |
| `constraints` | object | No | Restricciones de riesgo |
| `risk_tolerance` | string | No | conservative / moderate / aggressive |
| `selected_strategy` | object | No | Estrategia candidata para traza CoT |
| `signals` | list[object] | No | Señales de analistas |
| `evaluations` | list[object] | No | Evaluaciones del crítico |


| Campo | Tipo | Descripción |
|---|---|---|
| `bdi_state_id` | string | ID del estado BDI |

| `desires` | object | Deseos/restricciones |

```json

  "status": "ok",
  "data": {

      "approved": true,

    },
```

| Campo | Tipo | Descripción |

| `verdict.corrected_intention` | object | Intención corregida por Juice |
| `bdi_state` | object | Estado BDI completo |

## Seguridad y fiabilidad

1. **Separación BDI**: Beliefs son hechos derivados del mercado; Desires son invariantes. El LLM solo propone Intenciones.
2. **Juice como tribunal**: el filtro adversarial no pregunta "¿estás seguro?"; ejecuta reglas estructuradas y devuelve un `survival_score` cuantitativo.
3. **ReAct + CoT**: la cadena de pensamiento es observable y auditable; Juice detecta saltos lógicos.
4. **Commitment previo**: no hay ejecución sin `is_committed = True` y `survival_score >= 80`.
5. **Fallback seguro**: rechazo drástico dispara `HOLD` o `ESCALATE_HUMAN`.
