# DESCRIPTION

## 1. Objetivo

UC-277 implementa un **sistema avanzado de memoria multi-turno a largo plazo** para agentes. La memoria multi-interaccion permite a los agentes **mantener el contexto a lo largo de multiples interacciones en diferentes sesiones** con persistencia durante semanas o meses.

Con memoria, los agentes pueden:
- **Mantener objetivos a largo plazo** (semanas/meses).
- **Hacer seguimiento del progreso** en tareas complejas.
- **Personalizar experiencias** recordando preferencias del usuario.
- **Almacenar el historico completo** de sesiones en base de datos consultable.

## 2. Arquitectura del Sistema

### 5 Capas + Orquestador

| Capa | Modulo | Vida | Responsabilidad |
|---|---|---|---|
| 1. Working | `working_memory.py` | segundos/min | Contexto activo, capacidad 7+/-2, eviction por prioridad+recencia |
| 2. Episodic | `episodic_store.py` | dias/meses | Eventos con SQLite, busqueda semantica/temporal/tags/sesion |
| 3. Semantic | `semantic_memory.py` | permanente | Grafo de conocimiento: hechos, preferencias, relaciones |
| 4. Procedural | `procedural_memory.py` | permanente | Habilidades aprendidas, success_rate, mastery levels |
| 5. Goal | `goal_memory.py` | semanas/meses | Metas a largo plazo, sub-goals, milestones, tracking |
| Orquestador | `memory_system.py` | -- | MultiLayerMemorySystem: store, recall, consolidate |

### Flujo de Datos

```
INTERACCION
    |
    v
┌────────────────────────┐
│ MultiLayerMemorySystem │
│ store_interaction()    │
└───────┬────────────────┘
        |
        ├──> Working Memory (ultimo contexto)
        ├──> Episodic Store (SQLite, embedding)
        └──> Semantic Memory (si importance >= HIGH)

RECALL
    |
    v
┌────────────────────────┐
│ recall(query, layers)  │
└───────┬────────────────┘
        |
        ├──> Working (contexto activo)
        ├──> Episodic (similitud semantica + boost importancia/recencia)
        ├──> Semantic (grafo de conocimiento)
        ├──> Procedural (habilidades relevantes)
        └──> Goal (metas activas)

CONSOLIDACION
    |
    v
Episodic (high/critical) ──> Semantic (hechos permanentes)
```

## 3. Mecanismos Clave

### 3.1 Working Memory — Patron Miller (7+/-2)

Capacidad limitada con **eviction inteligente**:
- Score = `priority * exp(-(now - last_accessed) / 3600)`
- Items de baja prioridad y antiguos se descartan primero.
- Se limpia al inicio de cada nueva sesion.

### 3.2 Episodic Store — Busqueda Multi-Modal

| Tipo de Busqueda | Mecanismo |
|---|---|
| Semantica | embedding coseno + boost por importancia + recencia |
| Temporal | rango de timestamps |
| Por sesion | session_id (multi-sesion) |
| Por tags | filtro de etiquetas |

**Boost formula**: `score = similarity * exp(-0.01 * age_days) * (0.5 + importance_weight)`

### 3.3 Semantic Memory — Grafo de Conocimiento

- **Nodos**: hechos, preferencias (+/-), conceptos, entidades.
- **Aristas**: relaciones con fuerza y evidencia acumulada.
- **Deduplicacion**: si similitud > 0.85, refuerza nodo existente.
- **Confianza**: aumenta con validaciones repetidas.

### 3.4 Procedural Memory — Aprendizaje Progresivo

- **EMA (Exponential Moving Average)**: `score = alpha * new + (1-alpha) * old`
- **Mastery Levels**: novice -> struggling -> competent -> proficient -> expert
- **Refinamiento**: parametros actualizables desde autorreflexion.

### 3.5 Goal Memory — Tracking a Largo Plazo

- Metas con deadlines, sub-goals, prioridades.
- Milestones con timestamps para auditoria.
- Vinculacion con episodios y habilidades.
- Deteccion de metas vencidas (overdue).

---

## 4. Multi-Sesion y Persistencia

La persistencia permite que el agente **recuerde entre sesiones** (dias, semanas, meses):

1. **Fin de sesion**: working memory se limpia, episodic se persiste en SQLite.
2. **Inicio de nueva sesion**: episodios previos consultables via `recall_by_session(session_id)`.
3. **Consolidacion**: hechos importantes migran a memoria semantica permanente.
4. **Cross-sesion recall**: busqueda semantica funciona sobre TODAS las sesiones.

# API

## Card Views — Entrada

### `POST /api/v1/memory/store`
Almacena interaccion en sistema multi-capa (episodic + working + semantic).
```json
{
  "agent_id": "trading_agent",
  "summary": "Usuario solicito analisis de BTC/USD con horizonte semanal",
  "session_id": "sess_abc123",
  "episode_type": "trade",
  "details": {"pair": "BTC/USD", "timeframe": "1W"},
  "tags": ["btc", "analysis"],
  "importance": "high",
  "sentiment": 0.5,
  "extract_facts": true
}
```

### `POST /api/v1/memory/recall`
Recall multi-capa: busca en working + episodic + semantic + procedural + goals.
```json
{
  "agent_id": "trading_agent",
  "query": "preferencias del usuario sobre riesgo",
  "top_k": 5,
  "layers": ["episodic", "semantic", "goal"]
}
```

### `POST /api/v1/semantic/add-fact`
Agrega hecho permanente a memoria semantica (grafo de conocimiento).
```json
{
  "agent_id": "trading_agent",
  "content": "El usuario prefiere operaciones conservadoras con stop-loss",
  "node_type": "fact",
  "confidence": 0.9
}
```

### `POST /api/v1/goals/create`
Crea meta a largo plazo con tracking de progreso.
```json
{
  "agent_id": "trading_agent",
  "title": "Alcanzar 10% ROI mensual",
  "description": "Generar retornos consistentes del 10% mensual",
  "priority": 0.8,
  "deadline": 1735689600,
  "sub_goals": ["Mejorar win rate", "Reducir drawdown"]
}
```

### `POST /api/v1/episodic/search`
Busqueda semantica en memoria episodica con boost por importancia y recencia.
```json
{
  "agent_id": "trading_agent",
  "query": "BTC analisis de soporte",
  "top_k": 5
}
```

### `POST /api/v1/memory/consolidate`
Consolida memorias episodicas importantes a memoria semantica permanente.
```json
{
  "agent_id": "trading_agent"
}
```

## 8. Diferencias con UC-275 y UC-276

| Aspecto | UC-275 (Autorreflexion) | UC-276 (Recursive Prompting) | UC-277 (Memoria Multi-Turno) |
|---|---|---|---|
| **Foco** | Parametros internos | Output generado | Contexto entre sesiones |
| **Vida** | Dentro de la sesion | Dentro de la sesion | Semanas/meses/permanente |
| **Persistencia** | En memoria | En memoria | SQLite + embeddings |
| **Capas** | 1 (parametros) | 1 (versiones) | 5 (working, episodic, semantic, procedural, goal) |
| **Cross-sesion** | No | No | Si (multi-sesion real) |
| **Sinergia** | Ajusta COMO produce | Mejora QUE produce | Recuerda TODO lo que paso |
