## 1. Arquitectura de capas

```text
UC-315 (cerebro AGI canónico)
    ↓ consulta / decisión
UC-325 (reasoning loop autorreflexivo)
    ↓ pide evidencia refinada
UC-326 (MAQRI — memoria y búsqueda inteligente local)
    ↓ delega búsquedas externas a gran escala
UC-328 (ORQUESTA-R — Orquestador Resiliente de RAG Empresarial)
    ├── Router de fuentes
    ├── Cache distribuida
    ├── Federación de esquemas
    ├── Gestión de costo/latencia
    ├── Detección de conflictos
    ├── Filtros de privacidad/cumplimiento
    └── Fault tolerance + fallback
    ↓
Fuentes externas: APIs, vector DBs, SQL, documentos, etc.
```

UC-328 no modifica UC-315, UC-325 ni UC-326. Actúa como capa de orquestación entre UC-326 y el mundo externo, y también puede ser invocado directamente por UC-325 cuando se requieren búsquedas externas a gran escala.

## 3. Algoritmo ORQUESTA-R

```text
ENTRADA:
  - Consulta Q
  - Fuentes externas F = {f1, ..., fm}
  - Presupuesto B = {costo, latencia, concurrencia}
  - Políticas de privacidad P
  - Región del usuario R

SALIDA:
  - Respuesta sintetizada A
  - Veredicto de ejecución
  - Métricas y trazabilidad

FASE 0 — Inicialización:
  1. Cargar contexto persistente.
  2. Crear trace_id.

FASE 1 — Descomposición y planificación:
  3. Descomponer Q en subconsultas atómicas según capacidades.
  4. Calcular score = confiabilidad / (costo × latencia) por fuente.
  5. Seleccionar top-N fuentes por subconsulta.

FASE 2 — Federación de esquemas:
  6. Mapear campos de cada fuente al esquema canónico.
  7. Normalizar tipos, unidades y jerarquías.
  8. Limpiar nulos y duplicados.

FASE 3 — Ejecución con control de sobrecarga:
  9. Verificar caché antes de llamar fuente externa.
 10. Respetar presupuesto de costo y latencia.
 11. Limitar concurrencia y aplicar circuit breaker.
 12. Reintentar con backoff exponencial.

FASE 4 — Resolución de conflictos:
 13. Agrupar resultados parciales por subconsulta.
 14. Aplicar votación ponderada + decaimiento temporal.
 15. Detectar contradicciones con varianza.
 16. Verificar consistencia con contexto global.

FASE 5 — Contexto persistente y privacidad:
 17. Actualizar contexto global con versionado.
 18. Aplicar políticas GDPR/HIPAA/CCPA.
 19. Filtrar fuentes no conformes por región.

FASE 6 — Recuperación ante fallos:
 20. Health checks por fuente.
 21. Fallback a caché, fuente secundaria o valor estimado.
 22. Balanceo dinámico de carga.

FASE 7 — Síntesis y optimización:
 23. Calcular métricas finales (costo, latencia, fiabilidad).
 24. Generar recomendaciones.
 25. Empaquetar OrquestaResult.

FASE 8 — Entrega:
 26. Devolver respuesta con trazabilidad completa.
```

## 5. Uso desde Python

```python
from uc328 import UCOrquestaRLayer
from orquesta_models import OrquestaConfig, Budget, PrivacyPolicy

layer = UCOrquestaRLayer(
    config=OrquestaConfig(
        budget=Budget(max_cost=5.0, max_latency_ms=3000.0),
        privacy_policies=[PrivacyPolicy.GDPR],
    )
)

# Registrar fuente con conector
layer.engine.register_source({
    "name": "Bloomberg API",
    "source_type": "api",
    "cost_per_call": 0.50,
    "capabilities": ["fundamental", "news"],
}, connector=lambda q, meta: {"value": 123.0, "confidence": 0.92})

result = layer.orchestrate(
    query="Recommend technology stocks today",
    context="aggressive portfolio",
    user_region="EU",
)

print(result.to_dict())
```

## 8. Limitaciones y extensiones

- **Conectores externos**: los conectores reales a Bloomberg, Twitter, SEC deben implementarse por separado; ORQUESTA-R expone una interfaz inyectable.
- **Persistencia real**: la caché y el contexto actualmente son en memoria. En producción se reemplazan por Redis, vector DB y blob storage.
- **PII avanzado**: la detección de PII es basada en expresiones regulares; puede reemplazarse por NER.
- **Concurrencia**: la implementación actual es síncrona con control de presupuesto. En producción puede escalarse con workers asíncronos.
- **Multilingüe**: el router y las capacidades están orientadas a inglés; pueden extenderse con sinónimos en español.

---

## 9. Seguridad y gobernanza

- UC-328 no ejecuta acciones; solo recupera y sintetiza evidencia.
- El principio de seguridad aplica: *"Un modelo genera evidencia. La evidencia no es una orden."*
- Las decisiones finales permanecen en UC-315, mediadas por UC-325, UC-322 y UC-324.
- Datos sensibles se anonimizan antes de devolverse a capas superiores.
