## AI-Native Operations & Agentic Patterns
### CASE: UC-075 — Continuous Training Orchestrator

#### USO: INTERNO

UC-075 es una **capa externa** del ecosistema AGI que orquesta el reentrenamiento continuo de modelos desplegados en producción sin modificar los motores internos de otras UCs. Unifica:

- 4 estrategias de entrenamiento.
- 5 gates de validación para despliegues por lotes.
- Aprendizaje online incremental con **Circuit Breaker** y cuarentena de micro-lotes.
- Auditoría inmutable, MLflow/Prometheus/Grafana y aprobación humana (UC-290).

# DESCRIPTION

UC-075 responde a la pregunta: *¿cómo actualizamos modelos en producción de forma segura, justificada, observable y reversible?*

![Arquitectura UC-075](diagrama_interconexion_completo_uc075_uc162_uc290_uc300_uc308_uc309_uc317_uc330_uc087.png)

## Arquitectura batch (reentrenamiento por lotes)

```text
Trigger (SCHEDULED | EVENT_DRIVEN | ON_DEMAND | INCREMENTAL)
    ↓
TriggerEngine — política + presupuesto (fail-closed)
    ↓
VersionFreezeRegistry — dataset versionado con hash
    ↓
Trainer inyectado (UC-087 sandbox) → Candidato
    ↓
Evaluator inyectado (UC-308 out-of-sample) → ChampionCandidate
    ↓
GatePipeline (5 gates obligatorios, fail-fast)
    1. drift gate (UC-308 drift / olvido catastrófico incremental)
    2. champion_challenger gate (UC-308 / UC-087)
    3. security_fairness gate (UC-087 robustez, sesgo, backdoor, PII)
    4. hitl gate (UC-290 aprobación humana en alto impacto)
    5. canary gate (UC-320 / monitor inyectado)
    ↓
Decision: PROMOTE | REJECT | ROLLBACK | PENDING_HITL
    ↓
ChampionRegistry + Rollback automático + MLflowAdapter + Observability075 + AuditLog
```

## Arquitectura online (aprendizaje incremental con Circuit Breaker)

```text
Micro-lote entrante
    ↓
Integrity checkpoint — schema, tipos, nulos, rangos, tamaño
    ↓
Circuit Breaker — CLOSED | OPEN | HALF_OPEN
    ↓
Pre partial_fit concept drift — accuracy vs baseline
    ↓
partial_fit(model, X, y) con checkpoint previo
    ↓
Post partial_fit concept drift — detecta olvido / degradación
    ↓
Si OK → modelo productivo actualizado
Si FALLO → revertir pesos, cuarentenar lote, alertar Prometheus/Grafana
```

## Estrategias de reentrenamiento

| Estrategia | Cuándo | Control |
|---|---|---|
| `SCHEDULED` | Mantenimiento periódico (intervalo configurable). | `check_scheduled(agent_id, interval_hours)` |
| `EVENT_DRIVEN` | drift_score, error_rate, latency_degradation_pct, calibration_error, user_satisfaction, business_kpi_breach superan umbral. | `evaluate_metrics(...)` |
| `ON_DEMAND` | Cambio de producto, política, fuentes de datos o incidente. | `on_demand(...)` |
| `INCREMENTAL` | Mini-batch continuo con replay buffer ≥20% para evitar olvido catastrófico. | `incremental_step(...)` |
| `ONLINE` | Micro-lotes de alta frecuencia con `partial_fit` y Circuit Breaker. | `online_fit(...)` / `OnlineIncrementalLearner` |

## Gates obligatorios (pipeline batch)

```text
drift gate → champion_challenger gate → security_fairness gate → explainability gate → hitl gate → canary gate
```

- **FAIL en cualquier gate** detiene el run.
- **FAIL en canary** produce **rollback automático** al baseline.
- **REQUIRES_HITL** pausa el run hasta aprobación/rechazo humano.

## Circuit Breaker (pipeline online)

| Estado | Comportamiento |
|---|---|
| `CLOSED` | Acepta micro-lotes y aplica `partial_fit` tras validaciones. |
| `OPEN` | Rechaza actualizaciones; cuarentena todos los micro-lotes. |
| `HALF_OPEN` | Permite un número limitado de micro-lotes; si fallan vuelve a OPEN, si tienen éxito cierra el circuito. |

Transiciones:

- `CLOSED` → `OPEN`: fallo de integridad, error en `partial_fit`, o concept drift post-fit.
- `OPEN` → `HALF_OPEN`: transcurrido `cooldown_seconds`.
- `HALF_OPEN` → `CLOSED`: `half_open_max_batches` consecutivos exitosos.

## Gestión de riesgos AGI/MLOps

### Categorías de riesgo cubiertas

| Categoría | Ejemplos de riesgo | Controles en UC-075 |
|---|---|---|
| Datos | Data drift, concept drift, PII leak, data poisoning, procedencia dudosa | `VersionFreezeRegistry`, PII scan, drift gate, quarantine online |
| Modelo | Sobreajuste, sesgo, adversarial, alucinación, falta de explicabilidad | Security/fairness gate, ExplainabilityGate, champion/challenger, rollback |
| Agente | Autonomía excesiva, prompt injection, abuso de herramientas, cascada | HITL gate, least-privilege tools, tool allowlists, circuit breaker |
| Infraestructura | Downtime, misconfig, secret leak, supply chain | IaC, SBOM, DR plan, regional replication, failover |
| Organizativo | Sin owner, sin separación de funciones, sin respuesta a incidentes | Risk owner, runbooks, audit hash-chain, incident response |
| Regulatorio/negocio | Sanciones, pérdida de ingresos, pérdida de confianza | RegulatoryPolicy, jurisdiction rules, evidence preservation |

### Fórmula de riesgo residual

```text
inherent_risk = probabilidad × impacto × exposición
residual_risk = inherent_risk - efectividad_controles
```

### Severidades

| Residual | Severidad |
|---|---|
| ≥ 0.80 | critical |
| ≥ 0.60 | high |
| ≥ 0.35 | medium |
| ≥ 0.15 | low |
| < 0.15 | negligible |

### RiskGate en el pipeline

Tras pasar los gates técnicos, `RiskGate` evalúa el riesgo residual acumulado vinculado al run y a sus artefactos:

- Si hay riesgos `critical` abiertos → **congela** y escala a HITL.
- Si el riesgo residual máximo supera el umbral → **escala a HITL** o rechaza.
- Si el riesgo agregado supera el presupuesto → **escala a HITL**.
- Si está dentro de tolerancia → permite promoción.

Cada fallo de gate técnico se registra automáticamente como riesgo. Las cuarentenas online también generan riesgos de datos.

### Runbooks de respuesta

`RunbookCatalog` devuelve pasos y controles automáticos por categoría:

- `data` → congelar dataset, PII scan, cuarentena batch, revocar fuente RAG.
- `model` → rollback, canario shadow, tests adversariales, model card forense.
- `agent` → revocar credenciales, deshabilitar herramienta, aprobación humana, aislar agente.
- `infrastructure` → rotar secretos, failover, reconstruir imagen, escanear SBOM.
- `organizational` → asignar owner, actualizar inventario, plan de revisión.
- `regulatory` → legal hold, bloquear replicación, preservar evidencia, notificar DPO.
- `security` → revocar sesiones, parchear componentes, logs forenses.
- `business` → notificar stakeholders, BCP, revisar cobertura.

## Automatización de incidentes LLMOps con HITL

### Filosofía

- **Automatizar lo claro y repetible**, **escalar lo ambiguo, crítico o regulatorio**.
- Los humanos perfeccionan la automatización, identifican patrones novedosos y validan políticas.
- Simulacros periódicos y postmortem colaborativos mantienen la preparación.

### Categorías de incidente soportadas

| Categoría | Ejemplo | Respuesta automática |
|---|---|---|
| `data_drift` | Desviación estadística | Congelar dataset, reentrenar, notificar owner |
| `data_poisoning` | Lote envenenado | Cuarentena, abrir circuit breaker, notificar seguridad |
| `pii_leak` | Fuga de datos personales | Revocar acceso, enmascarar logs, notificar DPO |
| `model_degradation` | Caída de métricas | Rollback, canario shadow, reentrenar |
| `bias_violation` | Sesgo por subgrupo | Deshabilitar auto-promote, notificar equipo de fairness |
| `prompt_injection` | Inyección en input | Bloquear input, rotar guardrails, forense |
| `tool_abuse` | Uso indebido de herramienta | Revocar credenciales, deshabilitar herramienta, HITL |
| `agent_loop` | Bucle de ejecución | Terminar agente, volcar traza |
| `infrastructure_outage` | Caída / misconfig | Failover, page SRE, rotar secretos |
| `supply_chain` | Dependencia comprometida | Bloquear componente, escanear SBOM, rebuild |
| `regulatory_alert` | Brecha GDPR/HIPAA | Preservar evidencia, legal hold, notificar legal |
| `unknown` | Patrón novedoso | Forense, notificar SOC, **siempre escalar** |

### Reglas de escalación

Se escala a humano (`ESCALATED`) si:

- `confidence` < umbral del playbook.
- Severidad supera `max_auto_severity` del playbook.
- Categoría `regulatory_alert` (contexto regulatorio).
- Categoría `unknown` (patrón novedoso).
- Descripción contiene "destructive" o "ambiguous".

Cada escalación genera un riesgo en `RiskRegister` y emite métricas Prometheus.

### Simulacros (Drills)

`DrillSimulator` inyecta incidentes de prueba en modo dry-run y mide:

- Cuántos se auto-resolvieron.
- Cuántos se escalaron.
- Tiempo medio de triage.
- Hallazgos para actualizar playbooks.

### Aprendizaje de políticas

`PolicyLearningEngine` analiza incidentes resueltos y sugiere actualizaciones:

- `guardrails`: más validación ante inyecciones.
- `tool_policy`: doble aprobación para acciones destructivas.
- `data_validation`: provenance antes de indexar RAG.
- `playbook`: nuevo playbook para patrones novedosos.

### Baseline interpretable first

`RegulatedModelSelector` siempre evalúa primero un **baseline interpretable** (regresión lineal/logística, árbol pequeño, reglas). Si un sector exige interpretabilidad y no hay candidato interpretable aceptable, se **mantiene el baseline** aunque un black-box tenga mejor accuracy.

### Explainability Gate

Para sectores con `interpretability_required`:

- Modelos interpretables pasan automáticamente.
- Modelos black-box deben superar explicabilidad (LIME, SHAP, surrogate) con:
  - `stability_score >= 0.8`
  - `coverage >= 0.7`
- Si falla, el run se rechaza o se escala a HITL.

### Requisitos de stakeholders

`StakeholderRequirements` captura requisitos innegociables (CSO, CISO, Medical Board, Operaciones). Hasta que no se firmen, el selector bloquea el despliegue y mantiene baseline.

## MLOps global y multi-región

### Componentes

| Componente | Función |
|---|---|
| `GlobalMetadataStore` | Registro federado de artefactos con linaje, checksums y firmas. |
| `RegionalMetadataStore` + `RegionalArtifactCache` | Metadatos y caché por región para baja latencia. |
| `JurisdictionPolicy` | Residencia de datos, replicación permitida, cifrado y retención por jurisdicción (GDPR, CCPA, LGPD, PIPL, HIPAA). |
| `ArtifactLifecycleManager` | Tiering (hot/warm/cold/glacier), retención, garbage collection, legal hold. |
| `DisasterRecoveryPlan` | Backups, RPO/RTO y failover de región primaria. |

### Flujo de replicación

```text
Artefacto registrado en región origen
    ↓
JurisdictionPolicy valida residencia y destinos permitidos
    ↓
Réplica a regiones autorizadas
    ↓
Detección de conflictos (checksum mismatch, deleted/active, lineage break)
    ↓
Resolución automática (last_writer_wins / quorum) o escalado a HITL
```

### Ejemplo de registro global con GDPR

Cada run y cada micro-lote cuarentenado se registra en `AuditLog` / MLflow con hash-chain (verificable via `audit_chain_valid`). Datos capturados:

- `strategy_used`
- `drift_score`
- `business_trigger`
- `dataset_version`
- `model_version`
- `code_version`
- `mlflow_run_id`
- `update_status: QUARANTINED` + razón + métricas
- decisión final y aprobador

Alineado con **NIST AI RMF** e **ISO 42001**.

## Ejemplo: reportar y resolver un incidente LLMOps

```bash
# Reportar incidente de abuso de herramienta (escala a humano)
curl -X POST http://localhost:5075/api/v1/ct/incident/report \
  -H "Content-Type: application/json" \
  -d '{
    "category": "tool_abuse",
    "title": "Agente eliminó bucket S3",
    "description": "agent used aws delete_bucket on production",
    "source": "agent",
    "impact_score": 0.9,
    "affected_agents": ["agent-1"]
  }'

# Asignar a un analista
curl -X POST http://localhost:5075/api/v1/ct/incidents/<incident_id>/assign \
  -H "Content-Type: application/json" \
  -d '{"human": "analyst@utron.ai"}'

# Resolver con aprendizaje de política
curl -X POST http://localhost:5075/api/v1/ct/incidents/<incident_id>/resolve \
  -H "Content-Type: application/json" \
  -d '{
    "resolution_notes": "Bucket restaurado; se requiere doble aprobación",
    "policy_learnings": ["Requerir doble aprobación para delete_* en AWS"]
  }'

# Ejecutar simulacro
curl -X POST http://localhost:5075/api/v1/ct/incidents/drill \
  -H "Content-Type: application/json" \
  -d '{
    "scenario": "prompt-injection-weekly",
    "incidents": [
      {"category": "prompt_injection", "title": "t1", "description": "bypass", "impact_score": 0.6}
    ]
  }'
```

## Ejemplo: dominio regulatorio + selección de modelo
