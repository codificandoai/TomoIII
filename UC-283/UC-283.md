# Tomo III — UC-283

## Bucle gobernado de autocorrección para TrackPrice.ai

UC-283 implementa un sistema de autocorrección con evidencia determinista para decisiones de pricing. El generador no evalúa su propio resultado: un crítico independiente ejecuta challenge tests, las lecciones se persisten y un grafo LangGraph repite el ciclo hasta aprobar o agotar intentos.

```text
Observe -> Analyze/Fix -> Verify/Challenge -> Learn
              ^                              |
              +----------- retry ------------+
```

Las acciones de lectura y validación son automáticas. Aplicar un precio se clasifica como peligroso y requiere aprobación humana explícita.

## Grafo LangGraph

```text
START
  |
observe -- MCP get_market_context
  |
analyze_fix -- proposal or minimal correction
  |
verify_challenge -- independent deterministic critic
  |
learn -- persist lessons
  | pass/max attempts       | fail
 END <----------------------+----> analyze_fix
```

## MCP dinámico

El agente no tiene routing `if tool == ...`. `MCPToolServer` registra herramientas con definición, JSON Schema, handler y riesgo. El cliente usa:

1. `list_tools()` para descubrir capacidades.
2. `call_tool(name, arguments)` para invocar genéricamente.
3. Validación de campos requeridos, tipos, enums y argumentos desconocidos.
4. Gate de aprobación para herramientas peligrosas.

Herramientas incluidas:

| Tool | Riesgo | Función |
|---|---|---|
| `get_market_context` | safe | Fuente de verdad del mercado |
| `run_pricing_challenge` | safe | Ejecutar pruebas sobre propuesta |
| `apply_price` | dangerous | Aplicar precio, exige aprobación |

Agregar una herramienta no requiere modificar el agente:

```python
server.register(ToolDefinition(
    "forecast_demand",
    "Forecast demand",
    {"type": "object", "properties": {"price": {"type": "number"}}, "required": ["price"]},
), forecast_handler)
```

## Compuertas deterministas

El crítico devuelve score, métricas, errores y un registro por gate:

- Margen mínimo: 15%.
- Margen máximo: 60%.
- Gap máximo contra competidor: +15%.
- Gap mínimo: -5%.
- Cambio máximo: 2× volatilidad histórica.
- Precio positivo y finito.
- Umbral de aprobación: 80/100 sin errores pendientes.

El challenge test no acepta argumentos narrativos: cada gate reporta `passed` y `value`.

## Memoria Reflexion

Cada fallo produce una lección persistente:

```text
product_id + category + lesson + old_price + new_price
```

En el siguiente intento, el predictor recibe las últimas lecciones. La API expone estadísticas por categoría para detectar sesgos recurrentes.

## Seguridad y gobierno

- Reintentos acotados; no hay loop infinito.
- Crítico independiente del predictor.
- Evidencia obtenida mediante tools.
- Aplicación bloqueada sin `approved=true`.
- Sin ejecución arbitraria de comandos.
- Sin modificación automática de código o políticas.
- Hash SHA-256 de cada resultado.
- SQLite para aprendizaje entre sesiones.

# API REST

## Card view de entrada

`POST /api/v1/correct`

```json
{
  "product_id": "TRACKPRICE-SKU-123",
  "current_price": 249.99,
  "cost": 150.0,
  "competitor_price": 245.0,
  "historical_volatility": 5.5,
  "elasticity": -1.5,
  "base_demand": 5000,
  "max_attempts": 4,
  "apply": false,
  "approved": false
}
```

| Campo | Tipo | Requerido | Descripción |
|---|---|---:|---|
| `product_id` | string | Sí | SKU |
| `current_price` | number | Sí | Precio vigente |
| `cost` | number | Sí | Costo unitario |
| `competitor_price` | number | Sí | Precio competitivo |
| `historical_volatility` | number | Sí | Desviación típica |
| `elasticity` | number | No | Elasticidad negativa |
| `base_demand` | number | No | Demanda base |
| `max_attempts` | integer | No | Límite del loop |
| `apply` | boolean | No | Solicita aplicar |
| `approved` | boolean | No | Aprobación humana |

## Card view de salida

```json
{
  "status": "ok",
  "data": {
    "attempts": [
      {
        "number": 1,
        "proposed_price": 289.10,
        "critique": {
          "score": 45,
          "status": "fail",
          "errors": ["competitive_ceiling", "volatility"],
          "challenge_results": [
            {"gate": "competitive_ceiling", "passed": false, "value": 0.18}
          ]
        }
      },
      {
        "number": 2,
        "proposed_price": 249.99,
        "critique": {"score": 100, "status": "pass", "errors": []}
      }
    ],
    "final_price": 249.99,
    "status": "approved",
    "lessons": ["Avoid volatility; use deterministic feasible interval"],
    "audit_hash": "sha256..."
  }
}
```

Estados finales:

- `approved`: validado, no aplicado.
- `approval_required`: validado, aplicación bloqueada.
- `applied`: validado y aprobado explícitamente.
- `failed`: no converge dentro del límite.
