Implementaría políticas adaptativas como la de épsilon codicioso, donde el agente explota principalmente las mejores opciones disponibles, pero ocasionalmente explora alternativas. ## ALGORITMO: BALANCE-EX (Exploración-Explotación Adaptativa)

```
ENTRADA:
  - Agente A con conjunto de acciones posibles Acc = {a1, a2, ..., an}
  - Contexto actual C (vector de características del entorno)
  - Historial de interacciones H = {(c_t, a_t, r_t, c_{t+1})}
  - Parámetros iniciales:
      * epsilon_inicial = 0.3 (tasa de exploración inicial)
      * epsilon_min = 0.01 (tasa mínima de exploración)
      * tasa_decaimiento = 0.995 (factor de reducción por paso)
      * ventana_cambio = 100 (pasos para detectar cambios)
      * umbral_cambio = 0.15 (cambio significativo en recompensa)
      * alpha_aprendizaje = 0.1 (tasa de aprendizaje para Q-learning)
      * gamma_descuento = 0.95 (factor de descuento)
  - Presupuesto de exploración B_exp (opcional)
  - Horizonte temporal T (número total de pasos)

SALIDA:
  - Política π actualizada (mapeo contexto → acción)
  - Métricas de rendimiento:
      * Recompensa acumulada
      * Tasa de exploración actual
      * Regret acumulado
      * Detección de cambios ambientales
  - Registro de decisiones (para análisis y trazabilidad)

PROCEDIMIENTO:

FASE 0 - INICIALIZACIÓN DE ESTRUCTURAS:
----------------------------------------
1. Inicializar tabla Q (contexto, acción) con valores optimistas:
   - Para cada contexto posible (o representación vectorial), Q[c][a] = R_max
   - Usar modelos de bandidos contextuales: 
     * Modelo lineal: θ_a para cada acción (features → recompensa esperada)
     * Matriz de covarianza Σ_a para incertidumbre

2. Inicializar contadores:
   - N_acciones[a] = 0 (veces que se tomó cada acción)
   - Recompensa_acumulada_por_accion[a] = 0
   - Tasa_éxito_por_contexto[c][a] = 0.5 (neutral)

3. Configurar políticas de exploración:
   - Política principal: Epsilon-greedy adaptativo
   - Política secundaria: UCB (Upper Confidence Bound) para bandidos
   - Política terciaria: Thompson Sampling (para acción probabilística)

FASE 1 - DETECCIÓN DE CONTEXTO Y ESTADO DEL ENTORNO:
-----------------------------------------------------
4. Observar contexto actual C_t:
   a. Extraer características relevantes:
      - Variables de estado (posición, recursos, competidores)
      - Metadatos temporales (hora, día, estacionalidad)
      - Indicadores de cambio (tendencia, volatilidad)
   b. Normalizar características para modelo lineal

5. Detectar si el entorno ha cambiado significativamente:
   a. Calcular recompensa promedio en ventana deslizante:
      R_prom_actual = promedio(r_{t-ventana}...r_t)
      R_prom_anterior = promedio(r_{t-2*ventana}...r_{t-ventana})
   b. Si |R_prom_actual - R_prom_anterior| > umbral_cambio:
      - Marcar "cambio ambiental detectado"
      - Aumentar epsilon temporalmente (reinicio de exploración)
      - Resetear matrices de covarianza parcialmente
      - Registrar evento de cambio para análisis

FASE 2 - SELECCIÓN DE ACCIÓN CON POLÍTICA ADAPTATIVA:
------------------------------------------------------
6. Calcular tasa de exploración dinámica ε_t:
   a. Si hay cambio detectado:
      ε_t = min(epsilon_inicial, ε_t * 1.5)  // Aumentar exploración
   b. Si estamos en fase de explotación (pasos > 0.8*T):
      ε_t = max(epsilon_min, ε_t * 0.99)  // Reducir gradualmente
   c. Si hay presupuesto de exploración B_exp:
      ε_t = max(epsilon_min, min(epsilon_inicial, B_exp_restante / pasos_restantes))
   d. En caso normal (decaimiento estándar):
      ε_t = max(epsilon_min, epsilon_inicial * (tasa_decaimiento)^t)

7. Seleccionar acción usando estrategia híbrida:
   a. Generar número aleatorio u ~ Uniform(0, 1)
   b. Si u < ε_t (EXPLORAR):
      - Seleccionar entre múltiples métodos de exploración:
         * 40%: Exploración aleatoria (acción uniforme)
         * 30%: Exploración por UCB (acción con mayor incertidumbre)
         * 20%: Exploración dirigida (acción con potencial de aprendizaje)
         * 10%: Exploración por curiosidad (acción que maximiza novedad)
   c. Si u >= ε_t (EXPLOTAR):
      - Seleccionar acción con mayor Q-valor o mayor recompensa esperada:
         * Para cada acción a, calcular Q(c_t, a) según modelo
         * Elegir a* = argmax_a Q(c_t, a)
      - Si hay empate, desempatar por:
         * Acción con mayor número de pruebas (más confiable)
         * Acción con menor varianza (más estable)

8. Aplicar mecanismo de "exploración segura" (opcional):
   a. Si la acción seleccionada es nueva (N_acciones[a] < umbral_min_pruebas):
      - Reducir el riesgo tomando acciones de respaldo parcial
      - Ejecutar acción con un "paracaídas" (política mixta)
   b. Registrar la decisión con su contexto y justificación

FASE 3 - EJECUCIÓN DE ACCIÓN Y OBSERVACIÓN DE RECOMPENSA:
-----------------------------------------------------------
9. Ejecutar acción a_t en el entorno y observar:
   a. Recompensa inmediata r_t (escalar)
   b. Nuevo contexto C_{t+1}
   c. Señales adicionales:
      - Satisfacción del usuario (si aplica)
      - Tiempo de ejecución
      - Recursos consumidos

10. Calcular recompensa ajustada por riesgo (si es necesario):
    a. Si la acción era exploratoria (u < ε_t):
       - Aplicar bonificación por información ganada:
         r_ajustado = r_t + β * ganancia_información
       - Donde ganancia_información = entropía_reducida
    b. Si la acción era explotadora:
       - Aplicar penalización por sesgo de explotación:
         r_ajustado = r_t * (1 - 0.05 * (1 - ε_t))

FASE 4 - ACTUALIZACIÓN DE MODELOS Y APRENDIZAJE:
-------------------------------------------------
11. Actualizar modelo de bandido contextual (modelo lineal):
    a. Para cada acción a, actualizar:
       - θ_a ← θ_a + α * (r_t - θ_a^T * c_t) * c_t  // SGD
       - Σ_a ← Σ_a + c_t * c_t^T  // Información de Fisher
    b. Calcular incertidumbre para cada acción:
       - σ_a = sqrt(c_t^T * Σ_a^{-1} * c_t)  // Desviación estándar predictiva

12. Actualizar tabla Q (si se usa Q-learning):
    a. Para el par (c_t, a_t):
       Q[c_t][a_t] ← Q[c_t][a_t] + α * (r_t + γ * max_a' Q[c_{t+1}][a'] - Q[c_t][a_t])
    b. Para transiciones con recompensa negativa:
       - Reducir más agresivamente (factor de castigo 1.2)

13. Actualizar métricas de rendimiento por acción:
    a. N_acciones[a_t] ← N_acciones[a_t] + 1
    b. Recompensa_acumulada_por_accion[a_t] ← 
       Recompensa_acumulada_por_accion[a_t] + r_t
    c. Tasa_éxito_por_contexto[c_t][a_t] ← 
       (Tasa_éxito * (N-1) + (r_t > umbral_éxito)) / N

FASE 5 - AJUSTE DINÁMICO DE HIPERPARÁMETROS (Meta-aprendizaje):
-----------------------------------------------------------------
14. Evaluar rendimiento de la política actual:
    a. Calcular recompensa promedio en ventana reciente (últimos 50 pasos)
    b. Calcular regret acumulado:
       Regret = Σ (recompensa_óptima_estimada - r_t)
    c. Calcular diversidad de acciones (entropía de distribución):
       H_acciones = -Σ P(a) * log(P(a))

15. Ajustar parámetros adaptativamente:
    a. Si recompensa promedio < recompensa_histórica * 0.8:
       - Aumentar epsilon en 10% (más exploración)
       - Reducir gamma en 5% (más miope)
    b. Si la diversidad de acciones < 0.3 (demasiada explotación):
       - Aumentar tasa de exploración dirigida
       - Activar modo "curiosidad" (exploración por novedad)
    c. Si el regret acumulado crece rápidamente:
       - Activar modo de "reinicio parcial" (resetear pesos de acciones poco probadas)

16. Actualizar tasa de aprendizaje α adaptativamente:
    a. Si hay alta incertidumbre (σ_promedio > 0.5):
       - α = min(0.3, α * 1.1)  // Aprender más rápido
    b. Si el entorno es estable (sin cambios por > 100 pasos):
       - α = max(0.01, α * 0.99)  // Aprender más lento (estabilizar)

FASE 6 - GESTIÓN DE EXPLORACIÓN POR PRESUPUESTO:
-------------------------------------------------
17. Si hay presupuesto de exploración B_exp:
    a. Calcular costo de exploración:
       - Costo_acción_exploración[a] = tiempo_ejecución + recursos + riesgo
       - Si la exploración es costosa, usar:
          * Epsilon-greedy con presupuesto: 
            ε_t = min(ε_t, B_exp_restante / (T - t) * factor_seguridad)
    b. Si el presupuesto se agota:
       - Cambiar a modo "explotación pura" (ε = 0)
       - Activar estrategias de "exploración virtual" (planificación sin ejecución)

18. Si no hay presupuesto explícito:
    a. Usar "costo de oportunidad" de la exploración:
       - Si la exploración retrasa recompensas inmediatas, penalizar
       - Ajustar ε_t según beneficio esperado de exploración:
         ε_t = ε_t * (1 - factor_oportunidad)
    b. Donde factor_oportunidad = (recompensa_promedio - recompensa_exploración_promedio)

FASE 7 - DETECCIÓN Y REACCIÓN A ENTORNOS NO ESTACIONARIOS:
-----------------------------------------------------------
19. Monitorear estacionariedad del entorno:
    a. Usar prueba de Mann-Kendall para detectar tendencia en recompensas
    b. Usar prueba de Chow para detectar puntos de quiebre estructural

20. Si se detecta cambio significativo:
    a. Aumentar ε_t a epsilon_inicial (reinicio de exploración)
    b. Reducir α a 0.05 (aprender con cautela)
    c. Activar memoria de largo plazo:
       - Recordar acciones que funcionaron en contextos similares anteriores
    d. Aplicar "exploración basada en memoria":
       - 50% acciones probadas en contextos similares
       - 50% acciones completamente nuevas

21. Si se detecta ciclo o estacionalidad:
    a. Aprender patrón periódico:
       - Almacenar recompensas por período (hora, día, semana)
       - Usar promedio móvil estacional para ajustar expectativas
    b. En momentos de alta recompensa esperada:
       - Reducir ε_t (explotar más)
    c. En momentos de baja recompensa esperada:
       - Aumentar ε_t (explorar más para encontrar mejores oportunidades)

FASE 8 - APRENDIZAJE POR REFUERZO PROFUNDO (DRL) (OPCIONAL):
-------------------------------------------------------------
22. Si el espacio de estados es grande o continuo:
    a. Usar red neuronal profunda para aproximar Q(s, a):
       - Red: [estado_dim, 128, 128, 64, num_acciones]
       - Función de activación: ReLU
       - Optimizador: Adam (lr=0.001)
    b. Entrenar con experiencia replay:
       - Buffer de experiencias (10000 transiciones)
       - Batch size = 64
       - Target network actualizada cada 100 pasos

23. Implementar política de exploración en DRL:
    a. Epsilon-greedy con decaimiento (como en FASE 2)
    b. Bonus de exploración por curiosidad:
       - Error de predicción del modelo de dinámica (forward model)
       - Si el agente no puede predecir el siguiente estado → acción interesante

FASE 9 - ANÁLISIS DE RENDIMIENTO Y REGRET:
-------------------------------------------
24. Calcular regret acumulado y promedio:
    a. Regret_total = Σ (max_a Q(c_t, a) - Q(c_t, a_t))
    b. Regret_promedio = Regret_total / t
    c. Si Regret_promedio > umbral_regret:
       - Activar "modo de corrección" (exploración más agresiva)

25. Calcular métricas de balance:
    a. Tasa de exploración efectiva = acciones exploratorias / total
    b. Tasa de éxito = (recompensas > umbral) / total
    c. Ratio de explotación = 1 - tasa_exploración
    d. Índice de balance = tasa_exploración * tasa_éxito / (1 + variabilidad)

26. Generar recomendaciones de ajuste:
    a. Si tasa_exploración < 0.05 y tasa_éxito < 0.7 → "Necesita más exploración"
    b. Si tasa_exploración > 0.3 y tasa_éxito < 0.6 → "Exploración ineficiente"
    c. Si varianza de recompensa > 0.5 → "Entorno muy inestable, aumentar exploración"
    d. Si varianza de recompensa < 0.1 y tasa_éxito > 0.9 → "Fase estable, minimizar exploración"

FASE 10 - PLANIFICACIÓN Y SIMULACIÓN (MODEL-BASED RL):
-------------------------------------------------------
27. Si se permite planificación (modelo del entorno disponible):
    a. Simular M pasos hacia adelante usando modelo aprendido:
       - Para cada acción candidata, estimar recompensa esperada a largo plazo
       - Usar búsqueda de árbol Monte Carlo (MCTS) con:
          * Profundidad = 5
          * Ancho = 3 acciones por nodo
    b. Combinar planificación con exploración:
       - 60% seguir plan óptimo simulado
       - 40% explorar acciones con alto potencial (según plan)

28. Si no hay modelo disponible (model-free):
    a. Usar aprendizaje por refuerzo con "optimismo frente a incertidumbre"
    b. Inicializar Q con valores altos (principio de incertidumbre)

FASE 11 - EXPLORACIÓN POR CURIOSIDAD E INTRÍNSECA:
--------------------------------------------------
29. Calcular curiosidad intrínseca:
    a. Modelo de predicción de dinámica:
       - Entrenar red para predecir c_{t+1} dado (c_t, a_t)

    b. Bonus de recompensa por novedad:
       - r_intrínseco = η * error_de_predicción / (1 + error_promedio)
    c. Sumar a recompensa extrínseca:
```

```python
FUNCIÓN calcular_epsilon_adaptativo(estado, historial):
    // Epsilon basado en incertidumbre
    incertidumbre = calcular_incertidumbre_contexto(estado)
    if incertidumbre > 0.7:
        epsilon_base = min(0.4, incertidumbre * 0.5)
    else:
        epsilon_base = epsilon_inicial * (tasa_decaimiento)^t
    
    // Ajuste por rendimiento reciente
    rendimiento_reciente = recompensa_promedio(ventana=20)
    if rendimiento_reciente < umbral_malo:
        epsilon_base *= 1.2
    elif rendimiento_reciente > umbral_bueno:
        epsilon_base *= 0.8
    
    // Ajuste por diversidad de acciones
    diversidad = entropia(distribucion_acciones)
    if diversidad < 0.3:
        epsilon_base = max(epsilon_base, 0.15)  // forzar más exploración
    
    return max(epsilon_min, min(epsilon_inicial, epsilon_base))

FUNCIÓN seleccionar_accion_ucb(contexto, modelo, kappa=1.0):
    // Upper Confidence Bound
    for cada acción a:
        mu_a = modelo.predecir_recompensa(contexto, a)
        sigma_a = modelo.incertidumbre(contexto, a)
        ucb_a = mu_a + kappa * sigma_a * sqrt(log(t) / N_acciones[a])
    return argmax_a ucb_a

FUNCIÓN seleccionar_accion_thompson(contexto, modelo):
    // Thompson Sampling
    for cada acción a:
        theta_a ~ Normal(μ_a, σ_a)  // Muestrear de distribución posterior
        recompensa_esperada[a] = theta_a^T * contexto
    return argmax_a recompensa_esperada[a]

FUNCIÓN detectar_cambio_estructural(recompensas, ventana=100):
    // Prueba de Chow para puntos de quiebre
    n = len(recompensas)
    if n < 2*ventana: return False
    
    mejor_punto = None
    mejor_rss = inf
    for punto in range(ventana, n-ventana):
        rss1 = sum((r - mean(recompensas[:punto]))^2)
        rss2 = sum((r - mean(recompensas[punto:]))^2)
        rss_total = rss1 + rss2
        if rss_total < mejor_rss:
            mejor_rss = rss_total
            mejor_punto = punto
    
    // Calcular estadístico F
    rss_unido = sum((r - mean(recompensas))^2)
    F = ((rss_unido - mejor_rss) / 2) / (mejor_rss / (n - 4))
    
    // Si F > valor crítico, hay cambio
    return F > valor_critico_F(alfa=0.05)

FUNCIÓN calcular_curiosidad_intrinseca(estado, accion, estado_siguiente):
    // Modelo de predicción de dinámica
    estado_predicho = modelo_dinamica.predecir(estado, accion)
    error = MSE(estado_siguiente, estado_predicho)
    
    // Bonus de novedad (exploración intrínseca)
    error_normalizado = error / (1 + promedio_errores_historicos)
    bonus = eta * error_normalizado
    
    return bonus
```

## MÉTRICAS CLAVE DE BALANCE EXPLORACIÓN-EXPLOTACIÓN

| Métrica | Definición | Fórmula | Interpretación |
|---------|------------|---------|----------------|
| **Tasa de Exploración (TE)** | Proporción de acciones exploratorias | Acciones_aleatorias / Total_acciones | 0.05-0.30 = balance óptimo |
| **Regret Acumulado (RA)** | Pérdida por no elegir la óptima | Σ (R_opt - R_elegida) | Minimizar (ideal 0) |
| **Diversidad de Acciones (DA)** | Variedad de acciones tomadas | Entropía de distribución | >0.7 = buena diversidad |
| **Tasa de Éxito (TE)** | Proporción de acciones exitosas | Éxitos / Total | >0.8 = política efectiva |
| **Índice de Balance (IB)** | Balance exploración-explotación | TE * Tasa_Éxito / (1 + σ²) | >0.5 = buen balance |
| **Curiosidad Promedio (CP)** | Nivel de novedad explorada | Error_promedio_predicción | Alta = exploración intrínseca activa |

## EJEMPLO PRÁCTICO: AGENTE DE RECOMENDACIÓN DE INVERSIONES

**Escenario:** Agente recomienda acciones para invertir en bolsa

### Configuración:
- **Acciones:** 10 acciones diferentes (cada una con su perfil de riesgo)
- **Contexto:** indicadores (volatilidad, volumen, noticias, sector)
- **Objetivo:** Maximizar retorno ajustado por riesgo

### Ejecución del Algoritmo:

**Pasos 1-100 (Exploración temprana):**
- ε_t = 0.30 (alta exploración)
- Prueba todas las acciones al menos 5 veces
- Descubre que acciones tecnológicas son volátiles pero rentables

**Pasos 101-500 (Aprendizaje):**
- ε_t decae a 0.15
- Explota acciones tecnológicas (ganancia 12%)
- Ocacionalmente explora energías renovables (descubre potencial)

**Pasos 501-1000 (Especialización):**
- ε_t = 0.05
- Mayoría de tiempo invierte en tech (15% retorno)
- 5% explora nuevas oportunidades

**Cambio detectado en paso 750:**
- Caída del sector tecnológico (-5%)
- Algoritmo detecta cambio → ε_t sube a 0.25
- Explora sectores defensivos (salud, consumo básico)
- Descubre que salud da +8% en contexto de crisis

**Pasos 1000-2000 (Adaptación):**
- Política final: 60% tech (cuando estable), 30% salud (en crisis), 10% exploración
- Recompensa acumulada: +180% en 2000 pasos
- Regret promedio: 0.03 (muy bajo)

### Métricas Finales:
- **Tasa de Exploración Promedio:** 0.12
- **Tasa de Éxito:** 0.89
- **Diversidad de Acciones:** 0.72
- **Índice de Balance:** 0.68 (excelente)
- **Regret Acumulado:** 45 unidades (vs. 300 si solo explotara)

## ESTRATEGIAS DE EXPLORACIÓN-EXPLOTACIÓN COMPARADAS

| Estrategia | Ventajas | Desventajas | Cuándo usar |
|------------|----------|-------------|-------------|
| **Epsilon-greedy** | Simple, efectivo | No aprovecha incertidumbre | Entornos estables |
| **UCB (Upper Confidence Bound)** | Balancea explícitamente | Requiere modelo estadístico | Bandidos contextuales |
| **Thompson Sampling** | Óptimo probabilístico | Costoso computacionalmente | Espacios de acción grandes |
| **Curiosidad intrínseca** | Explora por novedad | Puede ser ruidosa | Entornos con recompensas escasas |
| **MCTS (Monte Carlo)** | Planifica a largo plazo | Lento en tiempo real | Problemas con horizonte largo |

| UC-296 | Almacena experiencias de exploración, resultados y patrones. |

## Seguridad

- **Explorar ≠ probar en producción.** Toda exploración de nuevas acciones ocurre en sandbox.
- **Gradiente de confianza:** `sandbox → validación → autorización UC-324 → explotación controlada → explotación plena`.
- **Rollback inmediato:** cada experimento en sandbox es reversible.
- **UC-330 no reemplaza al cerebro:** es un controlador de modo, no un decisor de acciones.
- **Curiosidad con presupuesto:** presupuesto de exploración por dominio y ventana temporal.
