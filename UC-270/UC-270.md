# DESCRIPTION

## 1. Objetivo

UC-270 implementa un **framework completo de resolución de conflictos entre agentes de IA** que integra los patrones y estrategias de tres repositorios de referencia:

| Fuente | Patrón integrado | Módulo |
|---|---|---|
| **OVADARE** (`nospecs/ovadare`) | Detección, clasificación y resolución de conflictos | `conflict_detector.py` |
| **NegMAS** (`yasserfarouk/negmas`) | Negociación bilateral/multilateral con concesiones | `negotiation.py` |
| **AutoGen** (discusión MS #7144) | Propose-Validate-Commit atómico con priorización y auditoría | `shared_state.py` |

---

## 2. Arquitectura del Pipeline

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ConflictManager (Orquestador)                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  1. DETECT & CLASSIFY (OVADARE)                                     │
│     ConflictDetector.detect(claims) → List[DetectedConflict]        │
│     • resource_contention                                           │
│     • incompatible_actions                                          │
│     • duplicate_ownership                                           │
│     • policy_violation                                              │
│                                                                     │
│  2. PRIORITIZE (if priorities differ)                               │
│     Regla directa: mayor prioridad gana                             │
│                                                                     │
│  3. NEGOTIATE (NegMAS — if equal priorities)                        │
│     NegotiationEngine.negotiate(conflict, profiles)                  │
│     • Rondas con concesiones progresivas                            │
│     • Zona de acuerdo: sum(shares) <= 1.0                           │
│     • Probabilidad de acuerdo: f(skill, flex, round)                │
│                                                                     │
│  4. ESCALATE (SuperiorAuthority)                                    │
│     Si negociación falla → scoring ponderado por autoridad          │
│     score = priority*0.40 + need*0.30 + willingness*0.15 +          │
│             reputation*0.15                                         │
│                                                                     │
│  5. COMMIT (AutoGen PVC)                                            │
│     SharedState.propose_validate_commit(proposal) → CommitRecord    │
│     • Validación atómica con lock                                   │
│     • Prioridad 0-3 (0=máxima)                                      │
│     • First-come-first-serve a igual prioridad                      │
│     • Auditoría completa con firmas SHA-256                         │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 4. Tipos de Conflicto y Severidad

### Tipos (ConflictType)
| Tipo | Condición |
|---|---|
| `resource_contention` | Suma de need > 1.0 sobre mismo recurso |
| `incompatible_actions` | Prioridades iguales, alta demanda |
| `duplicate_ownership` | Mismo agente reclama múltiples veces |
| `policy_violation` | Violación de políticas del sistema |

### Severidad (ConflictSeverity)
| Nivel | Condición |
|---|---|
| `critical` | priority >= 9 AND total_need > 1.5 |
| `high` | priority >= 7 OR total_need > 1.3 |
| `medium` | priority >= 5 |
| `low` | Otros casos |

---

## 5. Estrategias de Resolución

### 5.1 Priorización Directa
Si las prioridades de los agentes difieren, el de mayor prioridad gana inmediatamente sin negociación.

### 5.2 Negociación (NegMAS)
Cuando las prioridades son iguales:
- **Rondas iterativas** (configurable, default=5).
- **Concesiones progresivas**: cada ronda el agente reduce su demanda proporcionalmente a su flexibilidad.
- **Zona de acuerdo**: si `sum(shares) <= 1.05`, se normaliza y se asigna.
- **Probabilidad estocástica**: `prob = 0.35 + 0.25*avg_skill + 0.20*avg_flex + 0.05*round`.

### 5.3 Escalada (SuperiorAuthority)
Si la negociación falla (deadlock):
- Scoring ponderado: `priority*0.40 + need*0.30 + willingness*0.15 + reputation*0.15`.
- El agente con mayor score recibe el recurso.

### 5.4 Propose-Validate-Commit (AutoGen PVC)
Todo resultado se materializa mediante commit atómico al estado compartido:
1. **Propose**: el ganador propone escritura.
2. **Validate**: se verifica que no hay conflictos pendientes de mayor prioridad.
3. **Commit**: escritura atómica con registro de auditoría y firma criptográfica.

Variables de entorno (o defaults en `config.py`):

| Variable | Default | Descripción |
|---|---|---|

| `UC270_AGREEMENT_BASE_PROB` | 0.35 | Probabilidad base de acuerdo |
| `UC270_CONCESSION_RATE` | 0.10 | Tasa de concesión por ronda |

# API

## Card Views — Entrada

### `POST /api/v1/conflict/detect`
Detecta y clasifica conflictos a partir de reclamaciones.

```json
{
  "claims": [
    {"agent_name": "planner", "resource_id": "GPU_1", "need": 0.9, "priority": 8, "flexibility": 0.7, "willingness": 0.8},
    {"agent_name": "optimizer", "resource_id": "GPU_1", "need": 0.8, "priority": 8, "flexibility": 0.4, "willingness": 0.6}
  ]
}
```

### `POST /api/v1/conflict/resolve`
Pipeline completo: detectar + clasificar + negociar/priorizar/escalar + commit.

```json
{
  "claims": [
    {"agent_name": "planner", "resource_id": "GPU_1", "need": 0.9, "priority": 8, "flexibility": 0.7, "willingness": 0.8},
    {"agent_name": "optimizer", "resource_id": "GPU_1", "need": 0.8, "priority": 8, "flexibility": 0.4, "willingness": 0.6}
  ],
  "profiles": [
    {"name": "planner", "priority": 8, "flexibility": 0.7, "negotiation_skill": 0.8, "reputation": 0.9},
    {"name": "optimizer", "priority": 8, "flexibility": 0.4, "negotiation_skill": 0.6, "reputation": 0.7}
  ]
}
```

### `POST /api/v1/state/propose`
Propose-Validate-Commit atómico al estado compartido.

```json
{
  "agent_name": "planner",
  "resource_id": "GPU_1",
  "proposed_value": {"action": "allocate", "amount": 1.0},
  "priority_level": 0
}
```
